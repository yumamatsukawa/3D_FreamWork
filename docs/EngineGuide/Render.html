    Render(2D描画・カメラ・画面効果)

    Engine/Render/ は、画面に絵を出す仕組みの土台です。スプライト(画像)の描画、カメラ、カメラの揺れ、画面全体の演出(フラッシュ・暗転)、パーティクル(粒)、「カメラに映っているか」の判定が入っています。 スプライトの描き方は 3つのモード があります(SpriteMode)。迷ったらこの表を見てください。

    スプライトの3モード(SpriteMode): UI(既定)= HUD・ボタン・背景。z で大きさが変わらず、必ず最前面。 / World2D = 2D ゲームの物。遠近なしで、2D カメラでスクロール。z が小さいほど手前。 / World3D = 3D 空間に立てる板(ビルボード)。3D カメラの遠近で、3D メッシュと同じ深度で前後が決まる。

    Demo で見る: Demo プロジェクトの Render カテゴリに、Sprite / SpriteAnim / Camera / ScreenEffect / Transition / Particle / Tween / Coord の8個のデモがあります(Visibility は Render3D カテゴリ)。

    Engine/Render/SpriteRenderer.h Engine/Render/SpriteRenderer.cpp

    GameObject に「画像を描く見た目」を持たせる Component です。Unity の SpriteRenderer に相当します。transform.scale が画像の大きさ(2D ではピクセル)になります。

    名前引数・戻り値何をするか
    SpriteRenderer(const std::wstring& filepath, int cols, int rows)コンストラクタ画像のパスと、横・縦の分割数(cols / rows、既定は 1)。分割したコマの絵(スプライトシート)として使える
    SetTexture(const std::wstring& filepath, int cols, int rows)void後から画像を変える
    SetSpriteIndex(int index)void何コマ目を描くか(左上が 0。右へ、下の段へ)
    SetColor(float r, float g, float b, float a)void画像にかける色(白 1,1,1,1 でそのまま)
    GetColor()XMFLOAT4今の色
    SetMode(SpriteMode value)void描き方を選ぶ(UI / World2D / World3D)
    GetMode()SpriteMode今の描き方
    SetWorldSpace(bool v)void互換用。true = World3D、false = UI。新しく書く時は SetMode
    SetBillboardLock(bool lockX, bool lockY, bool lockZ)void3D モードのビルボード回転を軸ごとに止める(true の軸は回らない)
    SetBillboardLockX / SetBillboardLockY / SetBillboardLockZvoid1軸ずつ設定する版
    SetFrustumCulling(bool enabled)voidtrue で、画面の外にある時は描かない(物理は止まらない)
    IsFrustumCulling()bool画面の外を省く設定か
    使い方の例 出典: Sample2D/Game/Objects/Player.cpp:19-22
    // 見た目
auto* sprite = player->AddComponent<SpriteRenderer>(L"Assets/player.png", 8, 2);
sprite->SetSpriteIndex(5);
sprite->SetMode(SpriteMode::World2D);   // 2Dモード: zで大きさは変わらず、zが小さいほど手前(Playerはz=0。敵(+5)の手前、弾(-5)の奥)
    使い方の例 出典: Sample3D/Game/Components/EnemyManager.cpp:32-40
    // 見た目(3D空間に立つ2Dの画像)
auto* sprite = obj->AddComponent<SpriteRenderer>(L"Assets/player.png", 8, 2);
sprite->SetColor(1.0f, 0.0f, 1.0f, 1.0f);
sprite->SetWorldSpace(true);
// X/Zの傾きは固定し、水平方向(Y軸)だけカメラの方を向く「立て看板」にする。
// ※SpriteRendererのWorldモードはtransform.rotate.yを使わないので、
//   rotate.yで向きを変える代わりに、こちらで画像の表面を見る側に向けている
sprite->SetBillboardLock(true, false, true);
sprite->SetFrustumCulling(true);   // 画面の外にいる間は描かない(物理と動きは止まらない)
    気を付ける点
    • 既定の mode は UI です。UI も 2D カメラの位置でスクロールしますが、深度を使わず必ず最前面に描かれ、z では前後が決まりません(UI どうしは drawPriority → 作った順)。2D ゲームで「z で前後を決めたい物」(背景・壁・敵・Player・弾)は SetMode(SpriteMode::World2D) にします(Sample2D が実例)。画面に固定したい UI は、カメラの位置の分を足して置きます(Demo の DemoScreenFixController が実例)。
    • 3 モードの描画順は設計図の描画の順番を見てください。UI モードは「drawPriority → 作った順」で、z は使いません。
    • World2D の z は、3D カメラの z(既定 -500)より +5 以上奥 にします(Sprite.h のコメント)。z が小さいほど手前です。
    • 3D モード(ビルボード)は transform.rotate.y を使いません。向きを変える代わりに SetBillboardLock で軸を止めます。
    • SetFrustumCulling(true) は、HP バーや文字のように「画面に固定する物」には使いません。
    • GetDepthScale2D は 廃止 されました(2D では z で大きさが変わらないため)。古い資料にあっても使いません。

    Engine/Render/Image.h Engine/Render/Image.cpp

    描画の窓口です。2D 用カメラ・3D 用カメラ・ライトを持ち、座標の変換(ワールド ⇔ 画面)、画面に四角を塗る DrawRect、スプライト 1 枚を描く Draw を提供します。SpriteRenderer などが中で使うので、普段よく使うのは「カメラ」「座標の変換」「DrawRect」の3つです。

    カメラ・ライト

    名前引数・戻り値何をするか
    GetCamera()Camera&2D スプライト用のカメラ。position の x, y を動かすと画面がスクロールする
    GetCamera3D()Camera&3D メッシュ用のカメラ(2D とは別のもの)
    GetLight()Light&3D メッシュのライティングに使う、シーン共通の平行光源
    SetCamera3DAutoSync(bool enabled)void3D カメラを 2D カメラに自動で追従させるか(既定 true)。3D カメラを自分で操作する時は false
    GetAspectRatio()float3D 描画の縦横比(幅 ÷ 高さ)

    座標の変換(画面座標は、画面中央が (0,0)・Y+ が上・単位はピクセル)

    名前引数・戻り値何をするか
    WorldToScreen2D(XMFLOAT3 worldPosition)XMFLOAT22D カメラで、ワールド座標 → 画面座標
    ScreenToWorld2D(XMFLOAT2 screenPosition)XMFLOAT32D カメラで、画面座標 → ワールド座標(z は 0)
    WorldToScreen3D(XMFLOAT3 worldPosition)XMFLOAT33D カメラで、ワールド → 画面。z はカメラからの奥行き(0 以下はカメラの後ろで x, y は使えない)
    ScreenPointToRay3D(XMFLOAT2 screenPosition, XMFLOAT3& origin, XMFLOAT3& direction)void画面の点から奥へ伸びる線を求める(Physics::Raycast と組み合わせる)

    描く

    名前引数・戻り値何をするか
    DrawRect(XMFLOAT2 position, XMFLOAT2 size, XMFLOAT4 color)void画面に四角を1つ塗る(中心の画面座標、幅と高さ、色)。HP バーの帯など。カメラの影響を受けない
    Draw(Transform transform, unsigned int texID, XMFLOAT4 color, const SpriteSheet& sheet, SpriteMode mode, bool lockX, bool lockY, bool lockZ, BlendMode blend, bool depthWrite)void画像(texID)を1枚描く(SpriteMode 版。引数の lockX 以降は省略可)。bool worldSpace 版もある
    GetTextureView(unsigned int texID)ID3D11ShaderResourceView*Mesh などで画像を使い回したい時に、生の SRV を取り出す

    内部用(ゲーム側からは呼ばない)

    名前引数・戻り値何をするか

    BeginFrame() / EndFrame() / Uninit()voidフレームの始め・終わり・終了(GameEngine が呼ぶ)
    BeginUiQueue() / SetDrawOrder(int priority, int order) / FlushUiQueue()voidUI モードの描画を積んで、最後にまとめて描く仕組み(Scene::Draw が呼ぶ)
    DeferOverlay(std::function<void()> command)bool文字・四角などをオーバーレイキューに積む(Text / DrawRect が使う)。Scene::Draw の外では積まずに false
    FlushOverlayQueue()void積んだ文字・四角を呼んだ順に描く(Scene::Draw が呼ぶ)
    LoadTexture(path) / ReleaseTexture(id) / ReleaseAllTextures()unsigned int / void画像の読み込み。ゲーム側は Resources::LoadTexture を使う(こちらは共有されない)
    ReleaseDrawRectBrush()voidDrawRect のブラシの解放(GameEngine が呼ぶ)
    使い方の例 出典: Demo/Game/Components/Common/DemoMarker.cpp:7-21
    bool WorldToDemoScreen(DemoMode mode, const DirectX::XMFLOAT3& position, DirectX::XMFLOAT2& screen) {
    // 3Dはカメラの後ろ(z <= 0)にある点は出さない
    if (mode == DemoMode::Mode3D) {
        const DirectX::XMFLOAT3 projected = Image::WorldToScreen3D(position);
        screen = { projected.x, projected.y };
        return projected.z > 0.f;
    }
    screen = Image::WorldToScreen2D(position);
    return true;
}

void DrawDemoPoint(DemoMode mode, const DirectX::XMFLOAT3& position, float size, const DirectX::XMFLOAT4& color) {
    DirectX::XMFLOAT2 screen;
    if (WorldToDemoScreen(mode, position, screen)) Image::DrawRect(screen, { size, size }, color);
}
    使い方の例 出典: Sample2D/Game/Components/BackgroundController.cpp:26-31
    Transform tile;
tile.scale = { tileSize, tileSize, 1.f };
for (int y = minY; y <= maxY; y++) {
    for (int x = minX; x <= maxX; x++) {
        tile.position = { (x + 0.5f) * tileSize, (y + 0.5f) * tileSize, backgroundZ };
        Image::Draw(tile, texID, XMFLOAT4(1.f, 1.f, 1.f, 1.f), SpriteSheet(), SpriteMode::World2D);   // 2Dモード: いちばん奥(z=+100)に描く
    気を付ける点
    • 画面座標の Y+ は上 です。Input::GetMousePosition() は Y+ が下なので、ここへ渡す時は Y の符号を反転します(Input::GetMouseWorldPosition() は反転済み)。
    • WorldToScreen3D の結果は、使う前に必ず z > 0 を確かめます(カメラの後ろの点は画面に映りません)。
    • Draw の中で WorldToScreen○○ を呼ぶと、CameraShake の揺れが入ったカメラで計算されます(描いた絵と一緒に揺れる)。Update の中では揺れは入りません。
    • DrawRect は文字と同じ Direct2D で描き、UI スプライトより手前に出ます。Text::Draw とは呼んだ順に重なります。
    • 深度バッファは 2D・3D の物と 3D メッシュで使います。2D と 3D を同じシーンで混ぜることは想定していません。

    Engine/Render/Sprite.h Engine/Render/Sprite.cpp

    スプライト 1 種類ぶんの描画の中身(シェーダー・頂点バッファ・合成の設定)です。Image::Draw が中で使うので、ゲーム側が直接触ることはほとんどありません。ここにある SpriteMode と SpriteSheet と BlendMode は、ゲーム側からも使います。

    型

    名前引数・戻り値何をするか
    SpriteModeenum classUI(zで大きさが変わらず最前面)/ World2D(遠近なし・2D カメラでスクロール)/ World3D(3D カメラの遠近のビルボード)
    BlendModeenum class重ね方。Normal(普通)/ Additive(加算。炎・光向け)/ Soft(ふわっと。煙向け)
    SpriteSheetstruct画像の分割の指定。cols(横)・rows(縦)・index(何コマ目)
    Vertex / ConstantBufferstruct描画の内部で使うデータ(頂点・定数バッファ)。内部用

    Sprite クラス(内部用)

    名前引数・戻り値何をするか
    Init() / Uninit()bool / voidシェーダーなどの作成と解放(Image が呼ぶ)
    Draw(Transform transform, XMFLOAT4 color, const SpriteSheet& sheet, SpriteMode mode, bool lockX, bool lockY, bool lockZ, BlendMode blend, bool depthWrite)void1 枚描く(bool worldSpace 版もある)
    SetTexture(srv) / SetTextureSize(w, h) / GetTextureWidth() / GetTextureHeight()void / int使う画像と大きさの設定・取得
    SetCamera(const Camera*) / SetCamera3D(const Camera*)void2D 用 / 3D 用のカメラを渡す
    気を付ける点
    • Additive / Soft は、画像の 明るさ(RGB)で形と濃さ を表します(Shader.hlsl は「アルファ 0.5 未満は描かない」ため、アルファで半透明にする普通の方法ではふわっとなりません)。
    • SpriteRenderer の 2D / UI / 3D の選択は SetMode で行い、Sprite を直接使う場面はほぼありません。

    Engine/Render/Camera.h

    「どこから・どう見るか」を表すカメラです。2D 用(Image::GetCamera())と 3D 用(Image::GetCamera3D())の 2 つがあります。Unity の Camera の位置と投影の設定にあたります。

    名前引数・戻り値何をするか
    positionXMFLOAT3カメラ自身のワールド座標(既定 0, 0, -500)
    targetXMFLOAT3注視点(どこを見ているか)
    upXMFLOAT3上方向の基準(既定 0,1,0)
    fovYfloat縦方向の視野角(ラジアン、既定 45 度)
    nearZfloatこれより手前は描かない(既定 5)
    farZfloatこれより奥は描かない(既定 10000)
    focalLengthfloat3D カメラの視野角を 2D の画面と合わせるための基準距離(既定 500)。この距離にある 3D の物が 2D と同じ大きさに見える
    GetViewMatrix()XMMATRIXワールド → カメラ空間の行列
    GetProjectionMatrix(float aspectRatio)XMMATRIX透視投影の行列
    GetOrthographicMatrix(float width, float height, float nearZ, float farZ)static XMMATRIX正射影の行列(2D / UI 向け)
    使い方の例 出典: Sample3D/Game/Components/CameraController.cpp:79-96
    Camera& camera3D = Image::GetCamera3D();

if (mode == Mode::ThirdPerson) {
    camera3D.position = {
        focusPoint.x - forward.x * distance,
        focusPoint.y - forward.y * distance + thirdPersonHeight,
        focusPoint.z - forward.z * distance
    };
    camera3D.target = focusPoint;
}
else {
    camera3D.position = focusPoint;
    camera3D.target = {
        focusPoint.x + forward.x,
        focusPoint.y + forward.y,
        focusPoint.z + forward.z
    };
}
    気を付ける点
    • 2D カメラは普通 position の x, y だけ動かします(CameraFollowComponent が追いかけます)。
    • 3D カメラは既定では 2D カメラに自動で追従します。自分で GetCamera3D() を操作する時は Image::SetCamera3DAutoSync(false) にして、終わったら true に戻します(上の例の CameraController は Init と Uninit でそうしています)。
    • nearZ を極端に小さくすると、遠くの描画がちらつく(Z-fighting)ので 5 にしてあります。

    Engine/Render/CameraFollowComponent.h Engine/Render/CameraFollowComponent.cpp

    付けた GameObject を 2D カメラが追いかける Component です。Player などに付けます。Unity でいう Cinemachine の簡単版です。カメラの position の x, y だけを動かします。

    名前引数・戻り値何をするか
    SetOffset(XMFLOAT2 value)void対象からどれだけずらして映すか
    SetSmoothTime(float seconds)void追いつくまでの時間(秒)。0 = ピッタリ追従。負の値は 0
    SetBounds(XMFLOAT2 minCorner, XMFLOAT2 maxCorner)void画面に映してよい範囲(Z=0 平面の左下・右上)。外は映さない
    SetDeadZone(XMFLOAT2 size)voidこの大きさの四角の中で対象が動いても、カメラは動かさない
    Update(float dt) / OnActiveChanged(bool active)void内部で追従する処理(ゲーム側は呼ばない)
    使い方の例 出典: Sample2D/Game/Objects/Player.cpp:30-31
    // カメラがPlayerを追いかける(ピッタリ追従。SetSmoothTime(0.1f) などにすると少し遅れてなめらかに追う)
player->AddComponent<CameraFollowComponent>();
    使い方の例 出典: Demo/Game/Components/Render/CameraDemoController.cpp:80-87
    void CameraDemoController::SetFollow(CameraFollowComponent* followComponent) {
    follow = followComponent;
    if (!follow) return;

    // 最初の設定(なめらか・範囲あり)
    follow->SetSmoothTime(smoothTimes[smoothIndex]);
    follow->SetBounds({ -boundsHalf.x, -boundsHalf.y }, { boundsHalf.x, boundsHalf.y });
}
    気を付ける点
    • Component は付けた順に Update されます。 DynamicのRigidbody より 後(PhysX の結果の位置で追う)、Input::GetMouseWorldPosition() を使う Component より 前 に AddComponent します(Sample2D の Objects/Player.cpp が実例)。
    • 最初の Update と、SetActive(true) で戻った時は、なめらかに追わず一気に合わせます。2 つ以上のオブジェクトに付けると、後から Update された方が勝ちます。
    • なめらかな追従は dt で進むので、ポーズ中はカメラも止まります。

    Engine/Render/CameraShake.h Engine/Render/CameraShake.cpp

    画面を揺らします(2D カメラと 3D カメラの両方)。カメラの position を直接は変えず、「描画している間だけ」ずらして、描き終わったら元に戻します。

    名前引数・戻り値何をするか
    Shake(float strength, float duration)void強さ(2D はピクセル、3D はワールドの単位)と秒数で揺らす。揺れはだんだん弱まる。どちらかが 0 以下なら何もしない
    IsShaking()bool揺れている途中か
    Stop()void揺れをすぐ止める
    Update(float unscaledDt) / BeginDraw() / EndDraw()void内部用: GameEngine が毎フレーム呼ぶ
    使い方の例 出典: Sample2D/Game/Components/PlayerController.cpp:80-82
    // 画面を揺らして、画面の端を赤く点滅させる
CameraShake::Shake(damageShakeStrength, damageShakeDuration);
ScreenEffect::Vignette(damageVignetteColor, damageVignetteDuration, damageVignetteBlinkCount);
    気を付ける点
    • Update の中で読むカメラの値・Input::GetMouseWorldPosition()・CameraFollowComponent の計算には揺れが入りません。Draw の中で読む値と Image::WorldToScreen○○ には揺れが入ります。
    • 揺れの時間はポーズ中も進みます。シーンを切り替えると揺れは止まります。
    • 揺れている途中に Shake を呼ぶと、「今の(弱まった後の)強さ」より新しい方が強いか同じなら置き換え、弱ければ無視します。

    Engine/Render/ScreenEffect.h Engine/Render/ScreenEffect.cpp

    画面全体に色の演出(フラッシュ・ビネット・フェード)を重ねます。文字も含めて画面の一番上に描かれます。

    名前引数・戻り値何をするか
    Flash(XMFLOAT4 color, float duration)void画面全体が一瞬光る。color.w の濃さから duration 秒で 0 になる
    Vignette(XMFLOAT4 color, float duration, int blinkCount)void画面の端だけが色付きで点滅する(被弾の表現)
    Fade(XMFLOAT4 color, float toAlpha, float duration, std::function<void()> onComplete)void今の濃さから toAlpha(0〜1)へ duration 秒で変える(暗転・明転)。onComplete は変わり終わった時に1回呼ばれる
    IsFading()boolFade の濃さが変わっている途中か
    Stop()voidFlash と Vignette をすぐ消す(Fade は消さない)
    Update(float unscaledDt) / Draw() / OnSceneChanged() / Uninit()void内部用: GameEngine / SceneManager が呼ぶ
    使い方の例 出典: Demo/Game/Components/Render/ScreenEffectDemoController.cpp:34-37
    ScreenEffect::Fade(color, 1.f, fadeTime, [this, color] {
    completeCount++;
    ScreenEffect::Fade(color, 0.f, fadeTime);
});
    使い方の例 出典: Sample2D/Game/Components/PlayerController.cpp:80-82
    // 画面を揺らして、画面の端を赤く点滅させる
CameraShake::Shake(damageShakeStrength, damageShakeDuration);
ScreenEffect::Vignette(damageVignetteColor, damageVignetteDuration, damageVignetteBlinkCount);
    気を付ける点
    • 3つは別々に動き、同時に出せます。重なる順は下から Vignette → Flash → Fade です。
    • 時間はポーズ中も進みます(Time::GetUnscaledDeltaTime())。
    • シーンを切り替えると Flash と Vignette は消え、Fade の濃さは残ります(暗転したまま次のシーンへ行き、そこで明転できる)。ただし Fade の onComplete は、まだ呼ばれていなければ捨てられます。
    • onComplete は ScreenEffect::Update(シーンの Update の前)の中で呼ばれるので、中で ChangeScene してよい(同じフレームのうちに切り替わる)。
    • シーン切り替えの演出そのものは Transition の SceneTransition を使います(ScreenEffect::Fade は画面の色を変えるだけです)。

    Engine/Render/ParticleRenderer.h Engine/Render/ParticleRenderer.cpp

    小さい粒をたくさん出して描く Component です(爆発・煙・火花・炎)。Unity の ParticleSystem に相当します。粒 1 つ 1 つは GameObject ではなく、この Component の中のデータです。

    ParticleSettings の主な項目

    名前引数・戻り値何をするか
    texturestd::wstring粒の画像(空なら Assets/particle.png)。中心が白・外が黒の白黒画像
    emitRatefloat1秒に出す数(Play している間だけ。既定 10)
    lifetimeMin / lifetimeMaxfloat粒が消えるまでの時間(この間でランダム)
    speedMin / speedMaxfloat粒の速さ(この間でランダム)

    • 粒の数は最大 2000 個。超える分は出ません。
    • 粒の動きはシーンの時間(Time::GetDeltaTime)で進むので、ポーズ中は止まり、スローでは遅くなります。

    Engine/Render/Effect.h Engine/Render/Effect.cpp

    使い捨てのパーティクルのエフェクト(爆発など)を作る工場関数です。粒がすべて消えたら、オブジェクトも自動で消えます。

    名前引数・戻り値何をするか
    CreateEffect(Scene& scene, const ParticleSettings& settings, XMFLOAT3 position)GameObject*ParticleRenderer が付いたオブジェクトを作る(粒はまだ出ていない)。手前に描かれるよう drawPriority は大きい値

    // 作ったらすぐ粒を出す(出し終わったらEffectが自動で消える)

effect->GetComponent<ParticleRenderer>()->Burst(particleCount);

    気を付ける点
    • 作ったら すぐ Burst します。Burst の前に Update が回ると、粒が 0 のままなのですぐ消えます。
    • Play() で出し続けた場合は、Stop() して粒がすべて消えるまで残ります(Stop しないと消えません)。
