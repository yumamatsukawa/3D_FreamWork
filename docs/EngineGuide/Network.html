    Network(LAN 通信。ホストが計算して、結果を配る)

    Engine/Network/ は、同じ LAN につないだ 2〜4 台の PC で 1 つのゲームを一緒に遊ぶための仕組みです。方式はホスト式: 1 台が「ホスト」になってルールと物理(PhysX)の計算をホストだけで行い、「クライアント」は入力を送って、ホストから届いた結果(位置・向き)を表示します。PhysX は別の PC で同じ結果になる保証が無いので、みんなで同じ計算をするのではなく、「結果を配る」方式にしています。通信ライブラリは ENet(ThirdParty/enet/。MIT ライセンス)で、ゲームのコードは ENet を直接さわりません。

    ゲームが触るのは Network(窓口。名前空間)と、2 つの Component(NetworkIdentityComponent / NetworkTransformComponent)だけです。StartHost / Join / StartSearch を呼ばない限り何もしないので、Sample2D / Sample3D は変わりません(オフラインでも IsHost() は true、GetInput(0) は自分の入力で、1 人用としてそのまま動きます)。

    層は 4 つ: 通信(NetworkTransport + ENet)→ 部屋(NetworkSession / LanDiscovery)→ 同期(NetworkObjects / Identity / Transform)→ ゲーム側。GameEngine::Run の中の順番は、Input::Update → Network::Update(受信)→ Physics::Update → シーンの Update → Audio::Update → Network::EndFrame(送信)です(設計図のページの「1 フレームの流れ」の図にも出ています)。

    Demo で見る: Demo プロジェクトの Network カテゴリに、NetworkBasic(つなぐ・文字を送る)/ NetworkDiscovery(LAN のホストを探す)/ NetworkTransform(位置の同期。2D/3D)/ NetworkInput(入力の同期。2D/3D)/ NetworkEvent(スイッチと扉)/ NetworkSpawn(弾の出し入れ。2D/3D)の 6 つがあります。1 台で Demo.exe を 2 つ起動して試せます(README の §39)。

    Engine/Network/Network.h Engine/Network/Network.cpp

    ゲームが呼ぶ窓口です(Input / Audio / Time と同じ「名前空間 + 関数」の形で、Get() は無い)。ホストになる・探す・参加する、状態の取得、入力、出来事、共有の値、スポーン、シーンの同期をここに集めています。接続はシーンをまたいで残ります(アプリ全体で 1 つ)。

    気を付ける点
    • ルールを書く Component は、Update の最初に if (!identity->HasAuthority()) return; と書きます。クライアントでは動かさず、ホストが計算した結果を表示するだけにするためです。
    • クライアントのコピーを Dynamic にしてはいけません(クライアントの PhysX が勝手に動かし、ホストの位置とずれる)。工場関数で Network::IsHost() を見て、ホストは Dynamic、クライアントは Kinematic にします。
    • 「Host / Join を同じシーンの中で押す」デモでは、役割が変わった時に同期する物を作り直す必要があります(Demo の NetworkWorldController)。ロビーのシーンで先につないでからゲームのシーンへ移る作りなら要りません。
    • this を使うラムダを Subscribe / RegisterPrefab したら、Scene の Uninit で Network::ClearHandlers() を呼びます(EventBus::Clear() と同じ決まり)。
    • SceneManager は切り替え中の ChangeScene を無視するので、クライアントは切り替えが終わらなければ、2 秒ごとに最大 3 回やり直します。
    • タイムアウトは 10〜20 秒です(ウィンドウをドラッグしている間やデバッガで止めた間は、ゲームが止まって応答できないため)。
    • 同じ LAN の信頼できる相手が前提です(暗号化・認証・ずる対策は無い)。インターネット越し(ルーター越し)は対象外です。クライアント予測と Owner 権限は、まだ作っていません。

    Engine/Network/NetworkConfig.h

    ネットワークの定数を 1 か所に集めたファイルです。最大人数(maxPlayers)・通信の版(protocolVersion)・ポート(defaultPort / discoveryPort)・送る回数(defaultSnapshotRate / inputRate)・タイムアウト・上限の数などがあります。

    気を付ける点
    • 最大人数を変える時は、ここの maxPlayers だけを直します(1〜16 くらいまで。名簿・入力・Accept の人数に使われます)。
    • protocolVersion は、通信の仕様を変えた時に上げます。版が違う相手とは、つながらずに「Protocol version mismatch」で断られます。
    • static constexpr の camelCase で、Network:: の名前空間の中にあります(Network::defaultPort のように読む)。

    Engine/Network/NetworkMessage.h Engine/Network/NetworkMessage.cpp

    パケットの種類(PacketType)と、数値や文字を並べて書く NetworkWriter、読む NetworkReader です。NetworkReader は範囲外を読もうとすると 0 を返して「失敗」の印を付けるだけで、落ちません。浮動小数点が NaN / 無限大の時も失敗にします(壊れたパケット対策)。

    Network::Subscribe("SwitchPressed", [this](NetworkReader& payload, int sender) {
    const int index = payload.ReadU8();
    if (!payload.IsOk() || index < 0 || index > 1 || !Network::IsHost()) return;
    AddLog(L"スイッチ" + std::wstring(index == 0 ? L"A" : L"B") + L"が押された(プレイヤー" + std::to_wstring(sender) + L")");

    • 書く順番と読む順番を、送る側と受け取る側で同じにします(WriteString したら ReadString)。
    • 出来事の名前は 32 文字まで、中身は 512 バイトまでです。超えると送られず、出力ウィンドウに知らせます。

    Engine/Network/NetworkTransport.h Engine/Network/NetworkTransport.cpp

    ENet を包んだクラスです。接続・送信・受信だけを担当します。ENet を知っているのは、このファイルと LanDiscovery.cpp だけで、公開ヘッダーに enet/enet.h は出ません(enet.h は winsock2.h を読み込み、windows.h と衝突するため、ENet を読む .cpp は #include "enet/enet.h" を最初の行に書きます)。接続相手は peerId(整数)で呼びます。Network の外でも new できるので、ウィンドウ無しのテストで使えます。

    名前引数・戻り値何をするか
    StartServer(int port, int maxPeers)bool待ち受けを始める(失敗なら false)
    StartClient()bool接続する側の準備
    Connect(const std::string& address, int port)int接続を始める。相手の番号を返す(始められなければ -1)
    Stop()void全員に切断を知らせて(最大 0.2 秒待って)閉じる
    Poll(Event& out)bool溜まっている出来事(接続・切断・受信)を 1 つ取り出す。false になるまで呼ぶ
    Send(int peerId, int channel, const void* data, size_t size, bool reliable)bool送る。reliable が true なら必ず届く(届くまで送り直す)
    Flush()void溜めた送信をすぐ流す
    DisconnectPeer(int peerId)void溜めた送信を流してから切る
    SetTimeouts(int minMs, int maxMs)void応答が無い時に切るまでの時間
    GetPeerRoundTrip(int peerId)floatENet が測った往復の時間(秒)
    UpdateStats(float dt)void1 秒ごとの送受信量を数え直す
    気を付ける点
    • チャンネルは 3 つ: 0 = 信頼する通信(参加・出来事・スポーン)、1 = 入力・ping(信頼しない)、2 = 位置のスナップショット(信頼しない)。チャンネルが違えば、お互いを待ちません(信頼する通信の再送で、位置が遅れない)。
    • 信頼しない通信は、ENet が「古い物が新しい物の後に届いたら捨てる」順序付きで送ります。

    Engine/Network/NetworkSession.h Engine/Network/NetworkSession.cpp

    「今つながっているみんな」のまとまり(セッション)です。参加者の名簿・プレイヤー番号の割り当て・参加の受付(Join / Accept / Reject)・切断の検知・ping を担当します。入力・出来事・同期など、ゲームの中身のパケットは onPacket で上の層(Network)に渡します。

    Join(const std::string& address, int port, const std::string& playerName)bool参加を申し込む。つながったら Join パケットを送る
    Disconnect()void抜ける / 部屋を閉じる
    Update(float dt)void受信と、タイムアウト・ping の処理(毎フレーム)
    SendTo(int playerIndex, const NetworkWriter& packet, int channel, bool reliable)boolそのプレイヤーへ送る
    SendToAll(const NetworkWriter& packet, int channel, bool reliable, int exceptPlayer)voidホストだけ: 接続中のクライアント全員へ
    SendToHost(const NetworkWriter& packet, int channel, bool reliable)boolクライアントだけ: ホストへ
    GetPlayerCount()int今の人数
    GetPing()floatホストとの往復の時間
    気を付ける点
    • 断る理由: 満員(5 人目)/ 通信の版が違う / ゲーム ID が違う / 壊れた Join。断られたクライアントは GetLastError() に理由が入り、Offline に戻ります。
    • 番号の付け方: 一番若い空き番号(1〜3)を渡します。抜けた人の番号は、次に参加した人が使います。
    • 送り主のプレイヤー番号は、パケットの中身ではなく接続(peer)から決めます(偽装されない)。参加していない相手が送れるのは Join だけです。
    • 接続してから Join が来ない相手は、5 秒で切ります。

    Engine/Network/LanDiscovery.h Engine/Network/LanDiscovery.cpp

    LAN でホストを探す仕組みです。ゲーム本体とは別の UDP ポート(discoveryPort)を使い、探す側が LAN 全体へ呼びかけ(ブロードキャスト)、ホストが呼びかけた相手だけに返事(ゲーム ID・ポート・ホスト名・人数)を返します。ゲーム ID が違う相手は無視します。

    名前引数・戻り値何をするか
    StartResponder(const std::string& name, int port, int portOfDiscovery)boolホスト側を始める(探索用ポートを使えなければ false。使えなくても IP 直接入力では参加できる)
    StopResponder()voidホスト側をやめる
    StartSearch(int portOfDiscovery)bool探す側を始める(1 秒おきに呼びかける)
    StopSearch()void探す側をやめる
    Update(float dt)void呼びかけ・返事の処理。数秒返事が無いホストは一覧から消す
    GetFoundHosts()const std::vector<NetworkHostInfo>&見つかったホストの一覧
    GetLocalAddresses()static std::vector<std::string>このPCのIPv4アドレスの一覧
    気を付ける点
    • 呼びかけは、全体向け(255.255.255.255)・それぞれのネットワークの中向け(複数のアダプタがあっても届くように)・このPC自身(同じPCの別プロセス用)に送ります。
    • 学校・公共の Wi-Fi は、ブロードキャストや端末どうしの通信を禁止していることがあります。その時は探索が動かないので、IP アドレスの手入力(Join)を必ず残します。
    • 同じ探索用ポートを待ち受けられるのは 1 つのプロセスだけです。同じ PC の 2 つ目の Demo.exe は、探す側 / 参加する側として使います。

    AllocateSpawnId(double now)intスポーン用の NetworkId(1000〜65535)を 1 つ割り当てる。消したばかりの番号は 5 秒使わない
    気を付ける点
    • NetworkId は、シーンに置く物が 1〜999(ゲーム側が番号を付ける)、スポーンした物が 1000 以上(ホストが付ける)です。
    • 消した番号をすぐ使い回すと、古いスナップショットが新しい物に当たってしまうので、5 秒は使いません。

    Engine/Network/NetworkIdentityComponent.h Engine/Network/NetworkIdentityComponent.cpp

    同期する物に付ける印です(NetworkId・所有者・Authority)。ホストの物にも、クライアントのコピーにも同じ Component を付けます。違いは HasAuthority() が決めます。

    名前引数・戻り値何をするか
    SetSceneId(int id)voidシーンに最初から置く物の番号(1〜999)。ホストとクライアントで同じ番号にする
    GetNetworkId()int番号(0 = まだ無い)
    GetOwnerPlayerIndex()int所有者(この物を操作するプレイヤー)。-1 = 誰のでもない
    SetOwnerPlayerIndex(int playerIndex)void所有者を決める
    IsOwner()bool所有者が自分か
    HasAuthority()bool本当の状態を決める側か(ホストとオフライン = true、クライアント = false)
    SetSpawnInfo(int id, int prefab, int owner)void内部用: Network がスポーンの時に呼ぶ
    気を付ける点
    • 非アクティブ(ObjectPool に返した)になると登録簿から外れます。スポーンした物は番号を手放すので、次の Spawn で新しい番号が付きます(古い番号で登録し直されて、別の物とぶつからない)。
    • 同じ番号を 2 つの物に付けると、出力ウィンドウに知らせて、後の物が勝ちます。

    Engine/Network/NetworkTransformComponent.h Engine/Network/NetworkTransformComponent.cpp

    位置・向き(・大きさ)の同期です。ホストでは Transform を読んでスナップショットに入れ(30 回/秒)、クライアントでは届いた写真を 0.1 秒ほど遅れてなめらかにつないで、Transform に書きます。書く・読むタイミングは Network が決める(Update では何もしない。Rigidbody との順番の影響を受けないため)。

    名前引数・戻り値何をするか
    WriteState(NetworkWriter& writer)void内部用(ホスト): 今の Transform をスナップショットの 1 件として書く
    ReadState(NetworkReader& reader, double hostTime)bool内部用(クライアント): 1 件読んで写真を溜める(壊れていたら false)
    Interpolate(double renderTime)void内部用(クライアント): 表示の時刻に合わせて Transform に書く
    ClearSamples()void溜めた写真を捨てる
    LerpAngle(float from, float to, float t)static float角度(度)の補間。360 度をまたぐ時は近い向きに回る
    気を付ける点
    • 設定(NetworkTransformSettings): syncPosition / syncRotation / syncScale(変わった時だけ送る)/ is2D(position.xy と rotate.z だけ送る)/ teleportDistance(これ以上離れたら補間せずに飛ぶ。既定 500)。
    • 同期するのは親を持たない(ルートの)オブジェクトだけです。
    • 表示の時刻が最新より後(通信が遅れた)なら、最新の位置で止めます(予測では動かさない)。
    • 受け取った位置は ±1,000,000 に収め、NaN・知らない印・短すぎる写真は捨てます。

    Engine/Network/NetworkInput.h

    入力の中身です(2D / 3D どちらにも使える汎用の形)。軸 2 組(移動・視点)と、ボタン 16 個(押している状態と、押した瞬間)です。クライアントがホストへ送り、ホストが Network::GetInput で読みます。

    名前引数・戻り値何をするか
    SetButton(int bit, bool down)voidボタン(0〜15)の押している状態を決める。番号の意味(0 = Jump など)はゲーム側で決める
    IsButtonDown(int bit)bool押している間 true
    WasButtonPressed(int bit)bool押した瞬間だけ true(1 フレームの間)
    使い方の例 出典: Demo/Game/Components/Network/NetworkPlayerInputController.cpp:7-23
    void NetworkPlayerInputController::Update(float dt) {
    // 自分が操作する箱にだけ働く(ほかのプレイヤーの箱は、その人のPCが入力を送る)
    NetworkIdentityComponent* identity = GetOwner()->GetComponent<NetworkIdentityComponent>();
    if (!identity || !identity->IsOwner()) return;
    if (Time::IsPaused()) return;   // シーン切り替え中は受け付けない

    // 入力: 移動 = WASD または矢印キー(Q・E・Tab・Esc はデモの共通キーなので使わない)
    NetworkInput input;
    if (Input::GetKeyPress(KEY_D) || Input::GetKeyPress(KEY_RIGHT)) input.moveX += 1.f;
    if (Input::GetKeyPress(KEY_A) || Input::GetKeyPress(KEY_LEFT))  input.moveX -= 1.f;
    if (Input::GetKeyPress(KEY_W) || Input::GetKeyPress(KEY_UP))    input.moveY += 1.f;
    if (Input::GetKeyPress(KEY_S) || Input::GetKeyPress(KEY_DOWN))  input.moveY -= 1.f;
    input.SetButton(jumpButton, Input::GetKeyPress(KEY_SPACE));

    // 自分の入力を渡す(押した瞬間は Network が自動で計算する)
    Network::SetLocalInput(input);
}
    気を付ける点
    • 押した瞬間(pressed)は、SetLocalInput が前回との差から自動で計算します。クライアントは直近 3 回の送信に重ねて入れるので、パケットが 1 つ落ちても取りこぼしません。
    • 入力が 1 秒届かなかったら、ホストはその人の入力を 0 に戻します(押しっぱなしのまま止まらない)。
    • キーの割り当ては、ゲームによって違うので、集める Component は Engine ではなくゲーム側に置きます。
