    Behavior(動き・追跡・視野・経路探索)

    Engine/Behavior/ は、敵や物の「動きの頭脳」です。目的地へ向かう動き(Chase / AccelerateChase / Homing)、壁を避けて歩く経路探索(NavGrid / PathFinder / PathFollow)、見張り役の視野(Vision)が入っています。 動く平面は 2 種類です(MovePlane): XY(2D の画面)と XZ(3D の地面)。どちらも SetPlane で選びます(既定は XY)。

    目的地へ向かう動きの継承: MoveComponent(親。単体では付けない)← ChaseComponent / AccelerateChaseComponent / HomingComponent / PathFollowComponent。目的地は SetTarget(相手を追う)か SetTargetPosition(決まった場所)で決めます。

    Demo で見る: Demo プロジェクトの Behavior カテゴリに、Move / Homing / Vision / Path / MovingWall / TerrainPath の6個のデモがあります。

    Engine/Behavior/MoveComponent.h Engine/Behavior/MoveComponent.cpp

    「目的地へ向かって動く」Component の親クラスです。単体では AddComponent しません(コンストラクタが protected)。目的地・速さ・止まる距離・動く平面の共通の決まりを持ちます。

    名前引数・戻り値何をするか
    SetTarget(GameObject* newTarget)void追いかける相手(nullptr で外す)
    SetTargetPosition(XMFLOAT3 position)void決まった場所へ向かう(相手がいない時に使う)
    SetSpeed(float newSpeed)void速さ(1 秒に進む距離)。負の値は 0
    SetStopDistance(float distance)voidこれより近づいたら止まる
    SetPlane(MovePlane newPlane)void動く平面(MovePlane::XY か XZ。既定は XY)
    HasArrived()bool着いたか(目的地が StopDistance より近いか)
    GetTarget()GameObject*追いかけている相手
    GetSpeed()float速さ
    MovePlaneenum class動く平面: XY(2D)/ XZ(3D の地面)
    使い方の例 出典: Demo/Game/Objects/Behavior/MoveDemo.cpp:40-42
    auto* follow = followAgent->AddComponent<ChaseComponent>();
follow->SetPlane(GetDemoPlane(mode));
follow->SetTarget(targetMarker);
    使い方の例 出典: Demo/Game/Objects/Behavior/MoveDemo.cpp:51-53
    auto* point = pointAgent->AddComponent<ChaseComponent>();
point->SetPlane(GetDemoPlane(mode));
point->SetTargetPosition(ConvertPlaneToWorld(mode, is2D ? firstDestination2D : firstDestination3D, 0.f));
    気を付ける点
    • 目的地は、SetTarget の相手がいればその位置、いなければ SetTargetPosition の位置。どちらも無ければ止まります(速度 0)。
    • 相手が非アクティブ(SetActive(false) / Destroy 済み)の間は、追わずに止まります。相手の GameObject が Destroy されて本当に消えた後はポインタが消えた物を指したままになる ので、相手を消す時は、先に追いかけている側で SetTarget(nullptr) します。
    • 距離・向きは動く平面の上だけで考えます(XY なら Z の差、XZ なら Y の差は無視)。
    • 動かし方: Dynamic の RigidbodyComponent があれば SetVelocity。Kinematic か Rigidbody が無ければ transform.position を直接動かします。Static なら動かしません(出力ウィンドウに 1 回知らせます)。
    • XZ の時は Y 方向の速度(重力で落ちる速さ)をそのまま残します。XY の時は Z 方向の速度を 0 にします。
    • 壁にぶつけたい物は Dynamic にします(Kinematic は Static の壁をすり抜けます)。
    • ObjectPool で再利用した時(SetActive(true))に、速度などの状態がリセットされます(相手・速さなどの設定は残る)。

    Engine/Behavior/ChaseComponent.h Engine/Behavior/ChaseComponent.cpp

    目的地(相手・場所)へ、一定の速さでまっすぐ 向かう Component です。StopDistance(既定 1.0)より近づいたら止まります。壁は避けません(壁を避けたい時は PathFollowComponent)。

    名前引数・戻り値何をするか
    (専用の関数はありません)MoveComponent の関数を使うSetTarget / SetTargetPosition / SetSpeed / SetStopDistance / SetPlane / HasArrived
    Update(float dt)void (override)内部の処理
    使い方の例 出典: Demo/Game/Objects/Behavior/HomingDemo.cpp:46-49
    const MovePlane plane = GetDemoPlane(mode);
auto* chase = agents[0]->AddComponent<ChaseComponent>();
chase->SetPlane(plane);
chase->SetTarget(targetMarker);
    気を付ける点
    • 壁を避けなくてよい時(ごく近くの敵など)に向きます。
    • 2D の画面なら SetPlane は不要(既定が XY)。3D の地面の上を動く時は SetPlane(MovePlane::XZ)。

    Engine/Behavior/AccelerateChaseComponent.h Engine/Behavior/AccelerateChaseComponent.cpp

    目的地へ 加速しながら 向かう Component です。勢いがあるので、行き過ぎて戻ってきます。

    名前引数・戻り値何をするか
    SetAcceleration(float value)void加速の強さ(1 秒に速さがいくつ増えるか)
    SetMaxSpeed(float maxSpeed)void最高速度(SetSpeed と同じ)
    SetDrag(float value)void空気抵抗(0 で減速しない。大きいほどすぐ減速)。負の値は 0
    Update(float dt) / OnActiveChanged(bool active)void (override)内部の処理
    使い方の例 出典: Demo/Game/Components/Behavior/HomingDemoController.cpp:66-69
    chase->SetSpeed(chaseSpeed * unitScale);
accelerate->SetMaxSpeed(accelerateMaxSpeed * unitScale);
accelerate->SetDrag(accelerateDrag);
homing->SetSpeed(homingSpeed * unitScale);
    気を付ける点
    • StopDistance より近い間は加速をやめます(勢いのまま進み、空気抵抗で遅くなる)。
    • Dynamic の Rigidbody があれば AddForce(ForceMode::Acceleration) で加速します(ぶつかった時の跳ね返りも残る)。1 フレーム分の加速だけ、最高速度を少し超えることがあります(次のフレームで戻す)。
    • Kinematic か Rigidbody が無ければ、自分で速度を持って動かします。

    Engine/Behavior/HomingComponent.h Engine/Behavior/HomingComponent.cpp

    曲がれる角度に上限がある追尾です(ミサイル・車・魚向け)。今の進行方向を持ち、目的地の方へ 1 秒に最大 turnSpeed 度だけ曲がりながら、speed の速さで進みます。

    名前引数・戻り値何をするか
    SetTurnSpeed(float degreesPerSecond)void1 秒に何度まで曲がれるか(既定 180。負の値は 0)
    SetFaceMovement(bool enabled)void見た目の向き(rotate)も進行方向に合わせる
    Update(float dt) / OnActiveChanged(bool active)void (override)内部の処理
    使い方の例 出典: Demo/Game/Objects/Behavior/HomingDemo.cpp:53-56
    auto* homing = agents[2]->AddComponent<HomingComponent>();
homing->SetPlane(plane);
homing->SetTarget(targetMarker);
homing->SetFaceMovement(true);   // 見た目の向きも進行方向に合わせる
    気を付ける点
    • 最初の進行方向は、出した時の rotate の向きです。出す時に rotate を決めておけば、その向きへ飛び出してから曲がっていきます。
    • 進行方向の角度は rotate と同じ向きです(XY は rotate.z = Math::Forward2D、XZ は rotate.y = Math::Forward3D)。
    • Dynamic の剛体で SetFaceMovement(true) を使う時は SetFreezeRotation(true) にします(しないと PhysX の回転で上書きされます)。
    • 曲がれる角度に上限があるので、StopDistance を 0 に近くすると、目標の周りを回り続けることがあります。

    Engine/Behavior/PathFollowComponent.h Engine/Behavior/PathFollowComponent.cpp

    壁・障害物を避けながら、目的地へ一定の速さで向かう Component です。ChaseComponent の「まっすぐ向かう」を、経路探索つきにしたものです。経路は NavGridComponent の格子の上で探します(A* + 直線化)。

    名前引数・戻り値何をするか
    SetNavigation(NavGridComponent* newNavigation)voidどの格子で探すか(Spawn の度に渡す)
    SetRepathInterval(float seconds)void探し直す間隔(既定 0.5 秒。±20% ばらす。0.1 未満は 0.1)
    SetWaypointRadius(float distance)void次の点へ進む距離(既定は cellSize の半分)
    HasPath()bool経路が見つかっているか(止まっている時は false)
    GetPath()const std::vector<XMFLOAT3>&今の経路(確認・デバッグ用)
    SetDebugDrawEnabled(bool enabled)static voidtrue で今の経路を緑の線で描く
    Init() / Update(float dt) / Draw() / Uninit() / OnActiveChanged(bool active)void (override)内部の処理
    使い方の例 出典: Sample2D/Game/Components/EnemyManager.cpp:218-224
    // 追いかける相手・速さ・格子を渡す
PathFollowComponent* path = enemy->GetComponent<PathFollowComponent>();
if (path) {
    path->SetTarget(target);
    path->SetSpeed(enemySpeed);
    path->SetNavigation(navigation);
}
    使い方の例 出典: Sample2D/Game/Components/EnemyManager.cpp:45-46
    // 動き: 壁を避けて追いかける(追いかける相手・速さ・格子はSpawnで渡す)
obj->AddComponent<PathFollowComponent>();
    気を付ける点
    • SetTarget / SetSpeed / SetStopDistance / SetPlane は MoveComponent と同じです。
    • 経路が見つからない時は、止まります(格子の外にいる・目的地が格子の外・壁で囲まれている・格子がまだ焼けていない)。止まっている間も探し直すので、行けるようになったらまた動き出します。
    • 探し直すのは、一定の間隔・目的地が 1 マス以上動いた時・格子が変わった時・詰まった時(1 秒間に 速さ × 0.2 より進めなかった時)です。
    • 最後の点は目的地。目的地が通れないマスの中(壁際)なら、近くの通れるマスの中心まで行ってから、残りをまっすぐ向かいます。
    • ObjectPool で再利用した時に、経路・タイマーがリセットされます(相手・速さ・格子の設定は残る)。

    Engine/Behavior/NavGridComponent.h Engine/Behavior/NavGridComponent.cpp

    格子(NavGrid)と探索役(PathFinder)を持つ Component です。シーンに 1 つ置いて、PathFollowComponent に渡します。障害物(タグ "Wall" の Static な物)は、置くだけで自動で読み込まれます。

    名前引数・戻り値何をするか

    GetGrid()NavGrid&格子(障害物の登録・調べる)
    GetPathFinder()PathFinder&探索役
    SetTerrain(TerrainRenderer* newTerrain)void地形の高さ・傾きを取り込む(焼く前に渡す。焼いた後なら焼き直す)
    SetAutoRebakeInterval(float seconds)void自動で焼き直す間隔(0 = 焼き直さない。既定)。動く壁がある時だけ
    RequestRebake()void次のフレームで全体を焼き直す
    RebakeRegion(XMFLOAT3 center, XMFLOAT3 size)void範囲だけ、次のフレームの Update で焼き直す(動く壁を動かした側が呼ぶ。全体より軽い)
    SetMaxSearchesPerFrame(int count)void1 フレームの探索回数の上限(既定 8)
    IsBaked()bool最初の焼きが済んだか
    GetLastBakeMilliseconds()float直前の焼きにかかった時間(ミリ秒)
    TryBeginSearch()bool探索してよいか(PathFollowComponent が呼ぶ。上限に達していたら false)
    SetDebugDrawEnabled(bool enabled)static voidtrue で通れないマスの輪郭を赤い線で描く
    Update(float dt) / Draw() / Uninit()void (override)内部の処理
    使い方の例 出典: Sample2D/Game/Objects/Navigation.cpp:9-16
    // 格子の範囲: Playerが歩き回る範囲(原点のまわり6000四方)。外では敵は経路を探せず、止まる
NavGridSettings settings;
settings.origin = { -3000.0f, -3000.0f, 0.0f };
settings.size = { 6000.0f, 6000.0f };
settings.cellSize = 50.0f;           // 敵の大きさ(一辺100)の半分
settings.plane = MovePlane::XY;
settings.agentRadius = 50.0f;        // 敵は一辺100の四角
return navigation->AddComponent<NavGridComponent>(settings);   // Wall(タグ)は最初のフレームの後に自動で読まれる
    使い方の例 出典: Sample3D/Game/Objects/Navigation.cpp:10-21
    // 格子の範囲: Playerが歩き回る範囲(壁と丘をおおう9000四方)。外では敵は経路を探せず、止まる
NavGridSettings settings;
settings.origin = { -3000.0f, 0.0f, -3000.0f };
settings.size = { 9000.0f, 9000.0f };
settings.cellSize = 50.0f;           // 敵の半径(40)くらい
settings.plane = MovePlane::XZ;
settings.agentRadius = 40.0f;        // 敵は半径40のカプセル
settings.baseHeight = -50.0f;        // 地形の無い所の地面の高さ(Groundの上面)
auto* nav = navigation->AddComponent<NavGridComponent>(settings);   // Wall(タグ)は最初のフレームの後に自動で読まれる

// 丘の高さ・傾きを取り込む(急な斜面は通れないマスになる)
if (hills) nav->SetTerrain(hills->GetComponent<TerrainRenderer>());
    気を付ける点
    • 障害物を読む(焼く)のは 2 回目の Update です。物理に出したばかりの物は次のフレームから見つかるため、Init では読めません。焼き終わるまでは IsBaked() が false で、歩く側は待ちます。
    • 壁は先に置いてから NavGridComponent を置きます(Sample2D の GameScene は「壁をすべて置いた後に置く」)。
    • 動く壁(Kinematic)があるなら、SetAutoRebakeInterval で定期的に焼き直すか、動かした側が RequestRebake / RebakeRegion を呼びます。焼き直しは次のフレームの Update で行われます。
    • 探索の回数は 1 フレームに maxSearchesPerFrame までです(敵が多くても、探索が同じフレームに集中して重くならない)。
    • 3D の地形は SetTerrain で取り込むと、急な坂・大きな段差が通れないマスになります。

    Engine/Behavior/NavGrid.h Engine/Behavior/NavGrid.cpp

    地面を升目に区切って、各マスが「通れるか」(3D なら地面の高さも)を覚えておきます。経路探索(PathFinder)の土台です。2D(XY)でも 3D の地面(XZ)でも同じ形で使います。

    気を付ける点
    • 障害物は 3 種類を別々に覚えます: 手で登録(SetBlocked / SetBlockedBox)・物理から(BakeFromPhysics)・地形から(BakeFromTerrain)。どれか 1 つでも塞いでいれば通れません。焼き直しは、その種類の分だけを作り直します(手で登録した分は消えません)。
    • 障害物は agentRadius だけ太らせます(歩く物を「1 つの点」として扱うため)。
    • 格子は有限の範囲です。上限を超える設定は cellSize を自動で大きくして出力ウィンドウに知らせます。
    • 3D(XZ)は「平面の升目 + 各マスの地面の高さ」の 2.5 次元です。同じ XZ に床が複数ある場所(橋の下など)は扱えません。

    Engine/Behavior/PathFinder.h Engine/Behavior/PathFinder.cpp

    格子(NavGrid)の上で、A*(エースター)で最短の経路を探します。作業用の配列を 1 組だけ持って使い回します。ゲーム側が直接使うことは少なく、普通は PathFollowComponent が使います。

    名前引数・戻り値何をするか
    PathFinder(const NavGrid* newGrid)コンストラクタ探す格子を渡す
    FindPath(XMFLOAT3 start, XMFLOAT3 goal, const PathOptions& options)std::vector<XMFLOAT3>経路(ワールド座標の点の並び。先頭は start の次の点、最後は goal)。見つからなければ空
    GetLastExpandedCount()int直前の探索で調べたマスの数(確認用)
    PathOptions::smoothbool経路を直線化する(見通せる限り先の点へ飛ばす。既定 true)
    PathOptions::allowDiagonalbool斜めの移動を使う(8 方向。既定 true)。壁の角を斜めに抜けるのは禁止
    PathOptions::maxExpandedCellsint1 回の探索で調べるマスの上限(既定 20000。超えたら諦めて空の経路)
    気を付ける点
    • 1 つの PathFinder を同時に別々の探索には使えません(同じスレッドで順に呼びます)。
    • start / goal が通れないマス(太らせた障害物の中)なら、近くの通れるマスの中心に寄せてから探します。
    • start / goal が格子の外、寄せられる場所が無い、つながっていない、上限を超えた時は、空の経路になります。
    • smooth の時は、まっすぐ行けるなら探さずに [goal] だけを返します。

    気を付ける点
    • 壁に "Wall" のタグを付け忘れると素通しになります(視線がさえぎられない)。地面・ほかの敵・弾は壁になりません。
    • 相手の「1 点(位置)」だけを見ます。相手の中心が壁の陰なら、体が少しはみ出していても見えません。
    • 正面は SetFacing が最優先。無ければ XZ は Math::Forward3D(rotate.y)、XY は Math::Forward2D(rotate.z)。追いかける敵のように rotate を使わない物は、毎フレーム SetFacing で進む向きを渡します。
    • Raycast は 1 つ前の Physics::Update の位置を使うので、動いたばかりの壁には 1 フレーム遅れて反映されます。
    • 「カメラに映っているか」は Visibility の担当です(視野とは別)。
