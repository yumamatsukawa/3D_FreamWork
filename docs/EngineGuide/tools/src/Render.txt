=page Render
=title Render(2D描画・カメラ・画面効果)
=lead
`Engine/Render/` は、画面に絵を出す仕組みの土台です。スプライト(画像)の描画、カメラ、カメラの揺れ、画面全体の演出(フラッシュ・暗転)、パーティクル(粒)、「カメラに映っているか」の判定が入っています。
スプライトの描き方は **3つのモード** があります(`SpriteMode`)。迷ったらこの表を見てください。
=p
**スプライトの3モード(SpriteMode)**: `UI`(既定)= HUD・ボタン・背景。z で大きさが変わらず、必ず最前面。 / `World2D` = 2D ゲームの物。遠近なしで、2D カメラでスクロール。z が小さいほど手前。 / `World3D` = 3D 空間に立てる板(ビルボード)。3D カメラの遠近で、3D メッシュと同じ深度で前後が決まる。
=p
**Demo で見る**: Demo プロジェクトの **Render カテゴリ**に、Sprite / SpriteAnim / Camera / ScreenEffect / Transition / Particle / Tween / Coord の8個のデモがあります(Visibility は Render3D カテゴリ)。

=code Sample2D/Game/Objects/Player.cpp:19-22
=code Sample3D/Game/Components/EnemyManager.cpp:32-40
=notes
- 既定の `mode` は **UI** です。UI も 2D カメラの位置でスクロールしますが、**深度を使わず必ず最前面**に描かれ、z では前後が決まりません(UI どうしは `drawPriority` → 作った順)。2D ゲームで「z で前後を決めたい物」(背景・壁・敵・Player・弾)は `SetMode(SpriteMode::World2D)` にします(Sample2D が実例)。画面に固定したい UI は、カメラの位置の分を足して置きます(Demo の `DemoScreenFixController` が実例)。
- 3 モードの描画順は[設計図の描画の順番](architecture.html#draw)を見てください。UI モードは「`drawPriority` → 作った順」で、z は使いません。
- World2D の z は、**3D カメラの z(既定 -500)より +5 以上奥** にします(Sprite.h のコメント)。z が小さいほど手前です。
- 3D モード(ビルボード)は `transform.rotate.y` を使いません。向きを変える代わりに `SetBillboardLock` で軸を止めます。
- `SetFrustumCulling(true)` は、HP バーや文字のように「画面に固定する物」には使いません。
- `GetDepthScale2D` は **廃止** されました(2D では z で大きさが変わらないため)。古い資料にあっても使いません。

=role

SetCamera3DAutoSync(bool enabled) | void | 3D カメラを 2D カメラに自動で追従させるか(既定 `true`)。3D カメラを自分で操作する時は `false`
GetAspectRatio() | float | 3D 描画の縦横比(幅 ÷ 高さ)

WorldToScreen2D(XMFLOAT3 worldPosition) | XMFLOAT2 | 2D カメラで、ワールド座標 → 画面座標
ScreenToWorld2D(XMFLOAT2 screenPosition) | XMFLOAT3 | 2D カメラで、画面座標 → ワールド座標(z は 0)
WorldToScreen3D(XMFLOAT3 worldPosition) | XMFLOAT3 | 3D カメラで、ワールド → 画面。`z` はカメラからの奥行き(**0 以下はカメラの後ろ**で x, y は使えない)
ScreenPointToRay3D(XMFLOAT2 screenPosition, XMFLOAT3& origin, XMFLOAT3& direction) | void | 画面の点から奥へ伸びる線を求める(`Physics::Raycast` と組み合わせる)

GetTextureView(unsigned int texID) | ID3D11ShaderResourceView* | Mesh などで画像を使い回したい時に、生の SRV を取り出す

DeferOverlay(std::function<void()> command) | bool | 文字・四角などをオーバーレイキューに積む(Text / DrawRect が使う)。Scene::Draw の外では積まずに `false`
FlushOverlayQueue() | void | 積んだ文字・四角を呼んだ順に描く(Scene::Draw が呼ぶ)
LoadTexture(path) / ReleaseTexture(id) / ReleaseAllTextures() | unsigned int / void | 画像の読み込み。**ゲーム側は `Resources::LoadTexture` を使う**(こちらは共有されない)

=code Demo/Game/Components/Common/DemoMarker.cpp:7-21
=code Sample2D/Game/Components/BackgroundController.cpp:26-31
=notes
- 画面座標の **Y+ は上** です。`Input::GetMousePosition()` は Y+ が下なので、ここへ渡す時は Y の符号を反転します(`Input::GetMouseWorldPosition()` は反転済み)。
- `WorldToScreen3D` の結果は、使う前に必ず `z > 0` を確かめます(カメラの後ろの点は画面に映りません)。
- `Draw` の中で `WorldToScreen○○` を呼ぶと、`CameraShake` の揺れが入ったカメラで計算されます(描いた絵と一緒に揺れる)。`Update` の中では揺れは入りません。
- `DrawRect` は文字と同じ Direct2D で描き、**UI スプライトより手前**に出ます。`Text::Draw` とは呼んだ順に重なります。
- 深度バッファは 2D・3D の物と 3D メッシュで使います。2D と 3D を同じシーンで混ぜることは想定していません。

=file Engine/Render/Sprite.h, Sprite.cpp
=class Sprite, SpriteSheet, SpriteMode, BlendMode, Vertex, ConstantBuffer
=role
スプライト 1 種類ぶんの描画の中身(シェーダー・頂点バッファ・合成の設定)です。`Image::Draw` が中で使うので、ゲーム側が直接触ることはほとんどありません。ここにある `SpriteMode` と `SpriteSheet` と `BlendMode` は、ゲーム側からも使います。
=table 型
SpriteMode | enum class | `UI`(zで大きさが変わらず最前面)/ `World2D`(遠近なし・2D カメラでスクロール)/ `World3D`(3D カメラの遠近のビルボード)
BlendMode | enum class | 重ね方。`Normal`(普通)/ `Additive`(加算。炎・光向け)/ `Soft`(ふわっと。煙向け)
SpriteSheet | struct | 画像の分割の指定。`cols`(横)・`rows`(縦)・`index`(何コマ目)
Vertex / ConstantBuffer | struct | 描画の内部で使うデータ(頂点・定数バッファ)。内部用
=table Sprite クラス(内部用)
Init() / Uninit() | bool / void | シェーダーなどの作成と解放(Image が呼ぶ)
Draw(Transform transform, XMFLOAT4 color, const SpriteSheet& sheet, SpriteMode mode, bool lockX, bool lockY, bool lockZ, BlendMode blend, bool depthWrite) | void | 1 枚描く(`bool worldSpace` 版もある)
SetTexture(srv) / SetTextureSize(w, h) / GetTextureWidth() / GetTextureHeight() | void / int | 使う画像と大きさの設定・取得
SetCamera(const Camera*) / SetCamera3D(const Camera*) | void | 2D 用 / 3D 用のカメラを渡す
=notes
- `Additive` / `Soft` は、画像の **明るさ(RGB)で形と濃さ** を表します(`Shader.hlsl` は「アルファ 0.5 未満は描かない」ため、アルファで半透明にする普通の方法ではふわっとなりません)。
- `SpriteRenderer` の 2D / UI / 3D の選択は `SetMode` で行い、`Sprite` を直接使う場面はほぼありません。

=class CameraShake(名前空間)
=role
画面を揺らします(2D カメラと 3D カメラの両方)。カメラの `position` を直接は変えず、「描画している間だけ」ずらして、描き終わったら元に戻します。
=table
Shake(float strength, float duration) | void | 強さ(2D はピクセル、3D はワールドの単位)と秒数で揺らす。揺れはだんだん弱まる。どちらかが 0 以下なら何もしない
IsShaking() | bool | 揺れている途中か
Stop() | void | 揺れをすぐ止める
Update(float unscaledDt) / BeginDraw() / EndDraw() | void | 内部用: GameEngine が毎フレーム呼ぶ
=code Sample2D/Game/Components/PlayerController.cpp:80-82
=notes
- Update の中で読むカメラの値・`Input::GetMouseWorldPosition()`・`CameraFollowComponent` の計算には揺れが入りません。`Draw` の中で読む値と `Image::WorldToScreen○○` には揺れが入ります。
- 揺れの時間はポーズ中も進みます。シーンを切り替えると揺れは止まります。
- 揺れている途中に `Shake` を呼ぶと、「今の(弱まった後の)強さ」より新しい方が強いか同じなら置き換え、弱ければ無視します。

=file Engine/Render/ScreenEffect.h, ScreenEffect.cpp
=class ScreenEffect(名前空間)
=role
画面全体に色の演出(フラッシュ・ビネット・フェード)を重ねます。文字も含めて画面の一番上に描かれます。
=table
Flash(XMFLOAT4 color, float duration) | void | 画面全体が一瞬光る。`color.w` の濃さから `duration` 秒で 0 になる
Vignette(XMFLOAT4 color, float duration, int blinkCount) | void | 画面の端だけが色付きで点滅する(被弾の表現)
Fade(XMFLOAT4 color, float toAlpha, float duration, std::function<void()> onComplete) | void | 今の濃さから `toAlpha`(0〜1)へ `duration` 秒で変える(暗転・明転)。`onComplete` は変わり終わった時に1回呼ばれる
IsFading() | bool | Fade の濃さが変わっている途中か
Stop() | void | Flash と Vignette をすぐ消す(Fade は消さない)
Update(float unscaledDt) / Draw() / OnSceneChanged() / Uninit() | void | 内部用: GameEngine / SceneManager が呼ぶ
=code Demo/Game/Components/Render/ScreenEffectDemoController.cpp:34-37
=code Sample2D/Game/Components/PlayerController.cpp:80-82
=notes
- 3つは別々に動き、同時に出せます。重なる順は下から Vignette → Flash → Fade です。
- 時間はポーズ中も進みます(`Time::GetUnscaledDeltaTime()`)。
- シーンを切り替えると Flash と Vignette は消え、Fade の濃さは残ります(暗転したまま次のシーンへ行き、そこで明転できる)。ただし **Fade の `onComplete` は、まだ呼ばれていなければ捨てられます**。
- `onComplete` は `ScreenEffect::Update`(シーンの Update の前)の中で呼ばれるので、中で `ChangeScene` してよい(同じフレームのうちに切り替わる)。
- シーン切り替えの演出そのものは [Transition](Transition.html) の `SceneTransition` を使います(`ScreenEffect::Fade` は画面の色を変えるだけです)。

=class Visibility(名前空間)
=role
「カメラに映っているか」を調べる関数です(画面の外の物を描かない・処理を省く時に使います)。敵の視野(扇形)は [VisionComponent](Behavior.html#f-VisionComponent) を使います。
=table
IsSphereInView3D(XMFLOAT3 center, float radius) | bool | 3D カメラの視錐台に、球が少しでも入っているか
IsBoxInView3D(XMFLOAT3 center, XMFLOAT3 halfSize) | bool | 同じく箱(回転しない。`halfSize` は辺の長さの半分)
IsCircleInView2D(XMFLOAT3 position, float radius) | bool | 2D カメラの画面に円が少しでも入っているか
IsRectInView2D(XMFLOAT3 position, XMFLOAT2 halfSize) | bool | 同じく四角(回転しない)
GetCulledCount() | int | 前のフレームで、描かずに省いた数(確認用)
BeginFrame() / CountCulled() / IsTransformedSphereInView3D(world, localRadius) | void / bool | 内部用: GameEngine と各 Renderer が使う
=code Sample3D/Game/Components/GroundController.cpp:36-41
=notes
- 描画を省くだけで、**物理(当たり判定)は止まりません**。物が突然消えて見えたら、半径が小さすぎます(`GetCulledCount` で確認)。
- 3D の視錐台は 1 フレームに 1 回(`GameEngine` が作る)。最初のフレームなど準備前は「映っている(`true`)」を返します。
- `Update` の中で呼ぶと 1 つ前のフレームのカメラで判定します(敵の AI を省く程度なら問題ありません)。

=class Graphics(名前空間)
=role
DirectX11 の土台です(デバイス・描画先・深度バッファ・画面の大きさ)。`Image::Init` が中で初期化するので、ゲーム側は **画面の大きさ(`Graphics::width` / `height`)を読む** くらいです。
=table
width | extern float | ゲーム画面の幅(ピクセル)
height | extern float | ゲーム画面の高さ(ピクセル)
device | extern ID3D11Device* | DirectX11 のデバイス(内部用)
context | extern ID3D11DeviceContext* | 描画命令を出すコンテキスト(内部用)
swapChain | extern IDXGISwapChain* | 画面に出すための仕組み(内部用)
renderTarget | extern ID3D11RenderTargetView* | 描画先(内部用)
depthStencilView | extern ID3D11DepthStencilView* | 3D の前後関係のための深度バッファ(内部用)
Init(HWND hwnd, int w, int h) | bool | 初期化(内部用)
Uninit() | void | 解放(内部用)
=code Sample3D/Game/Components/CameraController.cpp:9-11
=notes
- `Graphics::width` / `height` は、ウィンドウの大きさではなく **ゲーム画面の解像度** です(`main.cpp` で渡した値)。マウス座標や UI の座標はこの単位です。

=class Texture(名前空間)
=role
画像ファイルを読み込む小さな道具です。`Image::LoadTexture` が使います。ゲーム側は `Resources::LoadTexture` を使うので、直接触りません。
=table
Load(const std::wstring& filepath) | LoadResult | 画像を読む。大きさ(`width`, `height`)と、描画用の `srv` を返す
LoadResult | struct | `srv`(描画で使う画像)・`width`・`height`
=notes
- 読み込めるのは RGBA 形式の png です(`Image::LoadTexture` のコメント)。
