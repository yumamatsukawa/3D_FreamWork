Engine 解説

3D_FreamWork の Engine(DirectX11 + PhysX 4.1 で作った、Unity 風の C++ ゲームフレームワーク)を、どのファイルに・どんな関数があって・どう使うかまで説明するページです。C++ やゲームエンジンに慣れていない人向けに書いています。 このフォルダの index.html をダブルクリックして開けば、インターネットが無くても見られます。

まず読む順番(おすすめ)

  1. このトップページで、全体像と「1 フレームの流れ」をつかむ。
  2. 設計図(図解)で、継承・持ち合い・描画の順番・物理・シーン切り替えの図を見る。
  3. Core(Component → GameObject → Scene → SceneManager)を読む。ここが一番大事です。
  4. 作りたいものに合わせて、Render(2D)/ Render3D(3D)/ Physics(当たり判定)/ UI などを読む。
  5. 分からない言葉は用語集、関数名やクラス名は左のメニューの検索やファイル索引で探す。
  6. 実際に動くものは、Demo プロジェクト(下の「Demo の開き方」)で見て、触って確かめる。

Engine の目的と、4 つのプロジェクト

Engine は「ゲームを作るための共通の部品」を集めた静的ライブラリ(Engine.lib)です。それだけでは動かず、下の 3 つの実行ファイルが同じ Engine を使います。Unity でいう「Unity 本体」にあたります。

プロジェクト種類中身
Engine静的ライブラリ全員が共通で使う機能(この解説の対象)。基本的にはみんなで触る場所ではありません。
Sample2D実行ファイルトップダウンの 2D アリーナシューター。2D ゲームの作り方の見本。
Sample3D実行ファイル3D 空間のショーケース(影・ライト・地形・水・モデルなど)。3D の作り方の見本。
Demo実行ファイルEngine の機能を機能ごとに小さなシーンで見せるデモ集(46 個)。見て・触って分かる。

Sample2D / Sample3D / Demo の中身は、どれも Game/Objects/(工場関数)・Game/Components/(動き・ルール)・Game/Scenes/(配置)に分かれています。この解説のコード例は、これらの実際のソースから引用しています(出典のファイル名と行番号つき)。

1 フレームの流れ(GameEngine::Run)

ゲームは「1 フレーム(約 1/60 秒)ごとに、更新して、描く」を繰り返します。その順番は GameEngine::Run(Engine/Core/GameEngine.cpp)に書かれていて、次のとおりです。順番には意味があります(例: 物理 → シーンの Update → 音、描く直前にカメラを揺らす、など)。

GameEngine::Run の 1 フレーム。前半が「更新」、後半が「描画」。

  • dt(前のフレームからの秒数)は Time::GetDeltaTime()。ポーズ中は 0 です。画面の揺れ・画面エフェクトだけは、止まらない時間(GetUnscaledDeltaTime)で進みます。
  • 各 Component の Update(dt) は、図の SceneManager::Update の中の Scene::Update で、付けた順に呼ばれます。
  • 描画の 3 つのパスの詳しい説明は設計図の「描画の順番」にあります。

はじめの一歩: GameObject を置いて Component を付ける

Engine の基本の形は 3 段階です。実際の Sample2D のコードで見てみましょう。

1. シーンに「何を置くか」だけを書く

Scene を継承したクラスの Init() に、Create○○(*this) を並べます。動きやルールは書きません。

2. 工場関数で、GameObject を作って Component を付ける

scene.CreateObject("名前", "タグ") で GameObject を作り、AddComponent<T>() で見た目や当たり判定を付けます。transform に位置と大きさを入れます。

3. 動きは Component に書く

Component を継承したクラスを作って、Update(float dt) などを override します。GetOwner() で付いている GameObject が分かります。

4. 起動と最初のシーン

ウィンドウを作ったあと、GameEngine を初期化して、最初のシーンを指定して、Run します(main.cpp)。

気を付ける点(はじめのうちに)
  • GetComponent<T>() の結果は、必ず nullptr かどうか調べてから使います。
  • Dynamic な物理の物は、transform を直接書き換えず、SetVelocity() で動かします。
  • 他の Component の情報が必要な時は、工場関数の引数でポインタを受け取ります。Get() を使うシングルトンは、EventBus / SceneManager だけです。
  • 新しいファイルを足したら、.vcxproj と .vcxproj.filters の両方に登録します(チームのルール: CLAUDE.md)。

Demo プロジェクトの開き方

Demo は、Engine の機能を「見て・触って分かる」ようにした専用の実行ファイル(Demo.exe)です。ゲーム(Sample2D / Sample3D)には影響しません。詳しくは README の §38 にあります。

  1. Visual Studio でソリューション(3D_FreamWork.sln)を開き、Demo を右クリック →「スタートアッププロジェクトに設定」して、F5 で実行する。
  2. または、ビルド済みの x64\Debug\Demo.exe(Release\ も)をダブルクリックする。
  3. 起動するとカテゴリ一覧(Core / Render / UI / Render3D / Physics / Behavior / Audio / Data の 8 個)が出る → 機能を選ぶ → デモが始まる。
  4. Tab キー(または右下のボタン)で、2D 版と 3D 版を切り替えられる(起動した時は 3D)。Esc で一つ前の画面へ戻る。

各ページの「Demo で見られる所」は、このカテゴリと機能名の案内です(例: 「Render カテゴリの Sprite」)。全 46 個のデモは、Demo の Game/Scenes/Common/DemoRegistry.cpp の一覧に並んでいます。

このガイドの使い方

  • 検索: 左のメニューの検索欄に、関数名・クラス名・ファイル名・説明の一部を入れると、全ページから探せます(インターネットは使いません)。
  • ファイル索引: files.html に、Engine の全ファイルの一覧があります。
  • 用語集: glossary.html に、Component・Rigidbody・Raycast などの用語を、Unity の同じ概念と対応させて説明しています。
  • 各ファイルの節に、主な関数の表(実際のヘッダーから拾っています)・使い方(Sample / Demo の実際のコード。出典の場所つき)・気を付ける点・Demo で見られる所・README の節番号があります。
  • 表に「内部用」と書いてある関数は、Engine の中だけで使う関数です。ゲーム側からは呼びません。
  • もっと詳しい説明や、決まりごと(命名規則・コメントの書き方)は、README.md と CLAUDE.md にあります。

このガイドを更新するには

ページの元データは docs/EngineGuide/tools/src/(.txt が各フォルダのページ、.html がトップ・設計図・用語集)、図は tools/make-diagrams.ps1 で作っています。Engine を変えたら、元データを直して tools/build.ps1 を実行します。コード例は「ファイル:行番号」から実際のソースを読み込むので、行がずれたら警告が出ます。
