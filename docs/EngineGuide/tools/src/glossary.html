基本の仕組み

Component(コンポーネント)
GameObject に付ける「部品」。見た目(SpriteRenderer)、動き(PlayerController)、当たり判定(RigidbodyComponent)など、1 つの機能を 1 つの部品にしたもの。Component を継承して作り、Init / Update / Draw などを書く。
Unity では: MonoBehaviour(と、Rigidbody などの組み込みコンポーネント)。 → [[Component]]
GameObject(ゲームオブジェクト)
ゲームの中の「物」の入れ物。それ自体は何もせず、名前・タグ・transform を持ち、Component を付けて見た目や動きを作る。
Unity では: GameObject。 → [[GameObject]]
Scene(シーン)
GameObject を入れておく入れ物で、ゲームの画面の単位(タイトル・プレイ画面など)。Init() に「何を置くか」だけを書く。
Unity では: Scene。 → [[Scene]]
SceneManager
今のシーンを持ち、シーンの切り替えを行う。アプリに 1 つだけ(SceneManager::Get())。
Unity では: SceneManager.LoadScene。 → [[SceneManager]]
Transform(トランスフォーム)
位置(position)・大きさ(scale)・回転(rotate、度)と、親子関係を持つ。子の position は「親から見た位置」(ローカル)。
Unity では: Transform。 → [[Transform]]
タグ(Tag)
GameObject に付ける種類の名前("Player"・"Enemy"・"Wall" など)。当たった相手の種類の判定や、Physics::Raycast / OverlapSphere の絞り込み、壁の判定に使う。
Unity では: Tag。
Init / Update / Draw / Uninit
Component が呼ばれるタイミング。Init は AddComponent の中で 1 回、Update(dt) は毎フレーム(動かす処理)、Draw は毎フレーム(描く処理)、Uninit は GameObject が消える時(後片付け)。
Unity では: Start / Update / OnDestroy にあたる(Draw に相当する物は Unity には無い)。
dt(デルタタイム)
前のフレームからの経過秒数。「1 秒に 100 動く」を「1 フレームに 100 * dt 動く」に直すために掛ける。
Unity では: Time.deltaTime。 → [[Time]]
TimeScale(時間の倍率)/ ポーズ
ゲームの時間の進み方。1 が普通、0.3 がスロー、0 がポーズ。ポーズ中も Update は呼ばれ続ける(dt が 0)。ポーズ中も動かしたい物は GetUnscaledDeltaTime() を使う。
Unity では: Time.timeScale。 → [[Time]]
Destroy と SetActive
Destroy() は「消す印」を付けるだけで、次の Scene::Update の最後に本当に消える。SetActive(false) は「お休み」(Update/Draw が止まる)で、消えない。
Unity では: Destroy と SetActive。
ObjectPool(オブジェクトプール)
弾や敵のように出しては消す物を、消さずに休ませて使い回す仕組み。作り直しの手間を減らす。借りた物には前回の値が残っているので、毎回セットし直す。
Unity では: ObjectPool<T>(UnityEngine.Pool)。 → [[ObjectPool]]
EventBus(イベントバス)
名前で識別する通知の仕組み。送る側は「何が起きたか」を知らせるだけ(Publish)、聞く側は名前で登録しておく(Subscribe)。お互いを知らなくてよい。
Unity では: C# の event / UnityEvent / メッセージ(Pub-Sub)。 → [[EventBus]]
Resources(リソース)/ 参照カウント
画像・音・モデルを何度も読み込まないための共有の仕組み。同じパスは 1 回だけ読み、何人が使っているか(参照カウント)を数える。
Unity では: アセットの共有(Resources.Load に近い名前だが、仕組みは別物)。 → [[Resources]]
シングルトン(Get())
アプリ全体で 1 つだけのサービス。このプロジェクトでは EventBus と SceneManager(と GameEngine)が Get() で取り出す。Input / Time / Audio / Physics などは名前空間の関数。
工場関数(Create○○)
GameObject を組み立てて返す関数(CreatePlayer(Scene&) など)。Game/Objects/ に置く。Scene は工場関数を並べるだけにする。
Timer(タイマー)
「○秒たったら」を数える小さな道具。Update(dt) が時間が来たフレームだけ true を返す。
Unity では: コルーチンの WaitForSeconds や自作のタイマー変数。 → [[Timer]]
CSV
カンマ区切りの表のファイル。Excel で編集できる。Csv::Load で読み、列の名前で値を取り出す。ファイルを保存し直すと、実行中に反映できる(ホットリロード)。 → [[Csv]]
SaveData(セーブデータ)
ハイスコアや音量を保存して、次の起動でも残す。
Unity では: PlayerPrefs。 → [[SaveData]]

描画

スプライト(Sprite)/ スプライトシート
画面に出す 1 枚の画像。1 枚の画像を格子に分けて、コマ(番号)を切り替えて使う物をスプライトシートという。
Unity では: Sprite / Sprite Sheet。 → [[SpriteRenderer]]
テクスチャ(Texture)
物の表面に貼る画像。Resources::LoadTexture で読むと ID(番号)で扱う。
UI モード / 2D モード / 3D モード(SpriteMode)
スプライトの描き方の 3 種類。UI(既定)= 必ず最前面・深度を使わない。2D(World2D)= 遠近なしで、z が小さいほど手前(深度バッファ)。3D(World3D)= 3D カメラの遠近で、カメラの方を向く板(ビルボード)。
Unity では: Canvas(UI)/ 2D の Sorting Order / 3D 空間の Billboard にあたる。 → 設計図: 描画の順番
drawPriority(描画の優先度)
描く順番を決める整数。小さいほど先に描かれる(既定 0)。スカイボックスは非常に小さい値にして最初に描く。
Unity では: Sorting Order / renderQueue に近い。 → [[GameObject]]
ビルボード(Billboard)
常にカメラの方を向く板。3D 空間に立てた 2D の絵(木・敵の画像)に使う。軸ごとに向きを止められる(SetBillboardLock)。
カメラ(2D カメラ / 3D カメラ)
「どこから見るか」。2D カメラ(Image::GetCamera())は position の x, y でスクロール、3D カメラ(Image::GetCamera3D())は遠近の透視。別々の物。
Unity では: Camera。 → [[Camera]]
深度バッファ(Depth Buffer)
画面の各ピクセルが「カメラからどれだけ遠いか」を覚えておく仕組み。手前の物が奥の物を隠すために使う。UI モードは使わない。
Unity では: Z-buffer / ZTest・ZWrite。
Z-fighting(ゼット・ファイティング)
2 つの面の深度が近すぎて、ちらついたり隙間が見えたりする現象。Camera::nearZ を極端に小さくしないのは、これを防ぐため。
視錐台(Frustum)/ カリング(Culling)
カメラに映る台形の空間を視錐台という。その外にある物を描かない(省く)ことをカリングという。SetFrustumCulling(true) や Visibility::IsSphereInView3D。描画を省くだけで、物理は止まらない。
Unity では: Frustum Culling。 → [[Visibility]]
合成(BlendMode)/ 加算合成
画像の重ね方。Normal(普通)/ Additive(加算。重なるほど明るくなる。炎・光向け)/ Soft(ふわっと。煙向け)。
Unity では: Blend Mode(Additive など)。
パーティクル(Particle)
小さい粒をたくさん出して、爆発・煙・火花を作る。粒 1 つは GameObject ではなく、ParticleRenderer の中のデータ。
Unity では: ParticleSystem。 → [[ParticleRenderer]]
画面エフェクト(Flash / Vignette / Fade)
画面全体に重ねる演出。Flash = 一瞬光る、Vignette = 画面の端が点滅、Fade = 暗転・明転。 → [[ScreenEffect]]
オーバーレイキュー
文字(Text::Draw)や四角(Image::DrawRect)を、Scene::Draw の間は描かずに待たせておき、UI スプライトの後に呼んだ順で描く仕組み。 → 設計図: 描画の順番
Direct2D
文字や四角を描くのに使っている Windows の 2D 描画の仕組み。カメラの影響を受けず、画像や 3D の後に重なる。

3D の見た目

メッシュ(Mesh)
3D の形(頂点の集まり)。立方体・球・カプセルを作る関数や、OBJ ファイルを読む関数がある。
Unity では: Mesh / MeshFilter。 → [[Mesh]]
マテリアル(Material)
3D の見た目の設定をまとめた物(色・画像・光沢・自発光・影・縁の光・枠線)。
Unity では: Material。 → [[Material]]
シェーダー(Shader)
GPU に「色をどう計算するか」を伝えるプログラム(.hlsl ファイル)。このプロジェクトでは Shader.hlsl(2D)・Shader3D.hlsl(3D)・Shader3DSkin.hlsl(骨で曲げる)・Shader3DWater.hlsl(水面)。全サンプル共通なので、触る時は相談が必要。
Unity では: Shader。
ライト(平行光源・点光源・スポットライト)
平行光源 = 太陽のように全体に同じ向きから当たる光(Image::GetLight())。点光源 = ランタンのように周りを照らす。スポットライト = 懐中電灯のように円すい形に照らす。点光源とスポットは LightComponent で最大 8 個。
Unity では: Directional / Point / Spot Light。 → [[LightComponent]]
法線(Normal)
面が向いている方向(長さ 1 のベクトル)。光の当たり具合の計算に使う。
光沢(Specular)/ 自発光(Emissive)
光沢 = つやつやしたハイライト。自発光 = 光の当たり方に関係なく、自分で光る色。どちらも Material の項目。
シャドウマップ(影)
光から見た深度を別のテクスチャに描いておき、「光から見て手前に別の物があるピクセル」を暗くする方法。既定は無効。 → [[Shadow]]
リム発光 / 枠線(アウトライン)
リム発光 = 輪郭に近い縁が光って見える効果。枠線 = 物の外側に描く太さ一定の線(壁越しにも出せる)。SetRimLight / SetOutline。
LOD(Level Of Detail)
遠い物を軽くする仕組み。このエンジンでは、遠い物を「描かない・影を落とさない・枠線を描かない」にする。
Unity では: LOD Group(ここでは省くだけの簡単版)。 → [[Lod]]
FBX / OBJ
3D モデルのファイル形式。ModelRenderer で描く。FBX はパーツの親子関係・アニメーション・骨(スキン)を持てる。
Unity では: モデルのインポート。 → [[ModelRenderer]]
スキン(骨・ボーン)/ スキンメッシュ
骨(ボーン)の動きに合わせて、形そのものを曲げる方法。人や生き物の滑らかな動きに使う。 → [[SkinMesh]]
地形(Terrain)/ 高さの画像(ハイトマップ)
丘や谷のある地面。高さの画像(白=高い、黒=低い)から作る。見た目は TerrainRenderer、当たり判定は TerrainRigidbodyComponent。
Unity では: Terrain / heightmap。 → [[Terrain]]
水面(Water)
波打つ半透明の面。波は頂点シェーダーが時間から計算する。当たり判定は付かない。 → [[WaterRenderer]]

物理

PhysX
NVIDIA の物理エンジン。このプロジェクトでは当たり判定も物理も全部 PhysX が計算する(2D のゲームでも同じ)。 → [[Physics]]
Rigidbody(剛体)
物理で動く・ぶつかる物の本体。このエンジンでは、形(Box / Sphere / Circle / Square / Capsule / Terrain)ごとの ○○RigidbodyComponent を付ける。
Unity では: Rigidbody + Collider を 1 つにした物。 → [[RigidbodyComponent]]
Collider(コライダー)
当たり判定の形。このエンジンでは剛体の形そのもの。コールバックで渡される Collider2D は「誰とぶつかったか」を伝える軽い札。
Unity では: Collider。 → [[Collider]]
Dynamic / Kinematic / Static
Dynamic = 重力や衝突で物理的に動く。Kinematic = 自分のコードが transform を動かす。Static = 完全に動かない(床・壁)。Kinematic の物は Static の壁とはぶつからず、すり抜ける。
Unity では: Dynamic / Kinematic / Static(Rigidbody の isKinematic など)。
Trigger(トリガー)
すり抜ける当たり判定。入った・出た・重なっている間を OnTriggerEnter / OnTriggerStay / OnTriggerExit で知る。ぶつかる判定(OnCollision○○)とは別。
Unity では: isTrigger + OnTriggerEnter。
Raycast(レイキャスト)
ある点から向きに沿って線を飛ばし、最初に当たった物を調べる。視線が壁にさえぎられるかの判定や、マウスで 3D の物を選ぶ時に使う。
Unity では: Physics.Raycast。 → [[Physics]]
Overlap(オーバーラップ)
球や箱の範囲に入っている物を、全部調べる(OverlapSphere / OverlapBox)。
Unity では: Physics.OverlapSphere / OverlapBox。
AddForce と ForceMode
物に力を加える。Force(押し続ける)/ Impulse(一瞬の衝撃)/ Acceleration(質量を無視して押し続ける)/ VelocityChange(質量を無視して一瞬で速さを変える)。
Unity では: Rigidbody.AddForce と ForceMode。
速度(Velocity)/ 質量(Mass)/ 空気抵抗(Drag)
速度 = 1 秒に動く量。質量 = 重さ。空気抵抗 = 速度が自然に落ちる強さ。Dynamic の物は SetVelocity で動かす(transform を直接書き換えない)。
Unity では: velocity / mass / drag。
100 単位 = 約 1m
このエンジンの長さの感覚。重力 981(= 9.81m/s² を 100 倍)も、このため。

動きと AI

Chase / AccelerateChase / Homing
目的地へ向かう動き 3 種。Chase = 一定の速さでまっすぐ。AccelerateChase = 加速しながら(行き過ぎて戻る)。Homing = 曲がれる角度に上限があって、弧を描いて追う。→ [[MoveComponent]]
NavGrid(ナビグリッド)
地面を升目に区切って、各マスが通れるかを覚えた地図。経路探索の土台。壁(タグ "Wall")を置くと自動で取り込まれる。
Unity では: NavMesh に近い(こちらは升目)。 → [[NavGrid]]
A*(エースター)/ 経路探索
升目の上で、障害物を避ける最短の道を探す方法。見つかった道を直線化して、点を順に目指して歩く。 → [[PathFinder]]
焼く(Bake)
障害物の情報を地図(NavGrid)に取り込むこと。動く壁がある時は、焼き直しが必要。 → [[NavGridComponent]]
視野(Vision)
見張り役の見える範囲(扇形)。角度と距離の中にいて、壁にさえぎられていなければ見える。 → [[VisionComponent]]

アニメーション

Tween(トゥイーン)
位置・大きさ・色などを、今の値から目標の値まで時間をかけて滑らかに変える仕組み。
Unity では: DOTween など。 → [[TweenComponent]]
Ease(イージング)
動きの「速さの変化」(ゆっくり始まる・ゆっくり止まる・跳ねる、など)。0〜1 の進み具合を 0〜1 の値に変える関数。
Unity では: AnimationCurve / DOTween の Ease。 → [[Ease]]
Lerp(リープ)
2 つの値の間の値を求める。Lerp(a, b, t) は、t=0 で a、t=1 で b。 → [[MathUtil]]
クリップ(Clip)/ CrossFade
名前の付いた 1 つの動き(歩く・待つなど)。Play("Walk") で再生。CrossFade は今のポーズから滑らかに切り替える。
Unity では: AnimationClip / Animator のブレンド。 → [[SpriteAnimationComponent]] / [[ModelAnimationComponent]]
クォータニオン(四元数)
3D の回転の表し方の 1 つ。回転の補間が滑らか。モデルのアニメーションの回転の補間に使っている。

UI・音・データ

Anchor(アンカー)
画面のどこを基準に置くか(左上・中央・右下など 9 か所)。画面サイズが変わっても、基準からの距離は変わらない。
Unity では: RectTransform のアンカー。 → [[Anchor]]
画面座標
画面の中央が (0,0)、Y+ が上、単位はゲーム画面のピクセル(Text::Draw と同じ)。Input::GetMousePosition() だけは Y+ が下なので注意。
ゲージ(Gauge)/ スライダー(Slider)/ ボタン(Button)
HP バーなどの帯(GaugeRenderer)、ドラッグで値を変える部品(SliderComponent)、クリックできるボタン(ButtonComponent)。
Unity では: UI の Image(Fill)/ Slider / Button。 → [[GaugeRenderer]]
AudioSource / AudioListener
音を鳴らす側と、聞く側。音は聞く側からの距離で小さくなり、左右の位置で聞こえる向きが変わる。
Unity では: AudioSource / AudioListener。 → [[AudioSourceComponent]]
AudioGroup(音のグループ)
BGM と SE ごとに音量を変えられる。Audio::SetGroupVolume。
Unity では: AudioMixer のグループ。 → [[Audio]]
WAV
このエンジンで読める音のファイル形式(WAV だけ)。音が鳴らない時は、WAV の中身を疑う。

C++ の言葉

virtual / override(継承と上書き)
親クラスの関数を、子クラスで書き換えること。Component の Update などは virtual で、子クラスが override して自分の動きを書く。
Unity では: virtual / override(C# と同じ)。
テンプレート(AddComponent<T>)
<> の中に型を書いて、その型に合わせた関数を使う書き方。GetComponent<SpriteRenderer>() は「付いている SpriteRenderer を探す」。
Unity では: GetComponent<T>()(C# のジェネリクス)。
ポインタ(*)と nullptr
物の「場所」を指す値。GameObject* は GameObject を指す。何も指していない時は nullptr。使う前に nullptr でないか調べる(GetComponent の結果は特に)。
unique_ptr / shared_ptr
持ち主が消えると自動で解放されるポインタ。unique_ptr は持ち主が 1 人、shared_ptr は何人かで共有(Terrain や Model)。new / delete を自分で書かなくてよい。
ラムダ式とコールバック
[this]() { ... } のような、その場で書く小さな関数。ボタンの onClick や EventBus の登録に渡す。this を取り込んだら、その寿命に注意(EventBus は Clear())。
Unity では: C# のラムダ式 / デリゲート。
namespace(名前空間)
関数をまとめる名前の箱。Input::GetKeyDown(...)・Math::Lerp(...)・Time::GetDeltaTime() の :: の左側。
ヘッダー(.h)と ソース(.cpp)
.h に「何があるか」(宣言)、.cpp に「どう動くか」(中身)を書く。この解説の関数の表は、ヘッダーから拾っている。
XMFLOAT2 / XMFLOAT3 / XMFLOAT4
DirectX の、小数 2・3・4 個の組(位置・向き・色など)。{ x, y, z } と書ける。+ - * は MathUtil.h で使えるようになる。
Unity では: Vector2 / Vector3 / Vector4 / Color。
BOM(ビーオーエム)
文字コード UTF-8 を示す印。日本語を含む .h / .cpp は BOM 付き UTF-8 で保存する(付いていないと、日本語ロケールの Visual Studio で文字化けやビルドエラーになる)。
