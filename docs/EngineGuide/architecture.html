    1. クラスの継承図

    動きや見た目を作る部品は、すべて Component を親(基底クラス)にして作られています。AddComponent<T>() で GameObject に付けられるのは、この木にある(または、あなたが Component を継承して作った)クラスです。 形(物理)の違いは RigidbodyComponent の子クラスで、目的地へ向かう動きの違いは MoveComponent の子クラスで表します。

    Component を頂点にした継承の木(Engine のヘッダーの class X : public Y をすべて拾ったもの)。MeshRenderer / ModelRenderer / TerrainRenderer は Component と Shadow::Caster の2つを継承します。SceneTransition の仲間は Component ではありません。

    Component 以外の主なクラス(GameObject・Scene・Transform・SceneManager・EventBus・ObjectPool など)は継承の木には入りません。Component を継承してあなたのゲームの Controller / Manager(PlayerController・GameManager など)を作るのが、普通の使い方です。

    Component 派生クラス数含まれるもの
    Component を直接継承21SpriteRenderer, ParticleRenderer, CameraFollowComponent, MeshRenderer, ModelRenderer, TerrainRenderer, WaterRenderer, LightComponent, RigidbodyComponent, MoveComponent, NavGridComponent, VisionComponent, TweenComponent, SpriteAnimationComponent, ModelAnimationComponent, AudioSourceComponent, AudioListenerComponent, TextRenderer, GaugeRenderer, SliderComponent, ButtonComponent
    RigidbodyComponent の子7Box / Sphere / Circle / Square / Capsule / Capsule2D / Terrain の各 RigidbodyComponent
    MoveComponent の子4ChaseComponent, AccelerateChaseComponent, HomingComponent, PathFollowComponent

    2. 持ち合いの関係(Scene / GameObject / Component)

    「誰が誰を持っているか」を知っておくと、「いつ消えるか」「どのポインタが危ないか」が分かります。

    実線 = 持っている(持ち主が消えると一緒に消える)。点線 = ポインタで知っているだけ(持ち主ではない)。

    • SceneManager は今の Scene を 1 つだけ持ちます(currentScene)。切り替えの演出中だけ SceneTransition も持ちます。
    • Scene は GameObject を std::unique_ptr の一覧(objects)で持ちます。シーンが終わる(Uninit)と全部消えます。
    • GameObject は Transform(メンバ)と Component の一覧を持ちます。
    • Component は GetOwner() で持ち主の GameObject を、GameObject は GetScene() で自分の Scene を知っています(ポインタ)。
    • 別のオブジェクトを指すポインタ(例: 追いかける相手 SetTarget)は、相手が消えると危険です。相手を消す前に、nullptr に差し替えます。
    • アプリ全体で 1 つのサービス: EventBus / SceneManager は Get() で、Input / Time / Audio / Physics / Image / Resources は名前空間の関数で使います。

    3. 生まれてから消えるまで

    GameObject と Component の一生。Init / Update / Draw / Uninit が呼ばれるタイミング。

    Scene::Update の中身(1 フレーム分)

    1. isUpdating = true にする(この間の CreateObject は待ち行列 pendingObjects 行き)。
    2. アクティブな GameObject すべてに Update(dt)。各 GameObject は、有効な Component を付けた順に Update。
    3. isUpdating = false に戻す。
    4. Destroy() された GameObject の Uninit() を呼び(各 Component の後片付け)、一覧から取り除く(ここで本当に消える)。
    5. 待ち行列にあった新しい GameObject を、一覧へ移す。
    • Component は付けた順に Update されます。順番が大事な組み合わせがあります(例: Dynamic の RigidbodyComponent → CameraFollowComponent → PlayerController の順に付ける。CameraFollowComponent の「決まり」)。
    • Destroy() は印だけです。同じフレームの残りの処理では、まだ使えます。
    • SetActive(false) は破棄ではなく「お休み」です(Update / Draw が止まり、全 Component に OnActiveChanged(false) が届く)。
    • ポーズ中(Time の倍率 0)も Update は呼ばれ続けます(dt が 0)。入力を止めたい Controller は Time::IsPaused() を見ます。

    5. 描画の順番と 3 つのモード

    GameEngine::Run の中で、Scene::Draw が3 つのパスで描き、そのあとに画面エフェクトとシーン切り替えの演出が一番手前に重なります。

    下ほど先に描かれ(奥)、上ほど後に描かれます(手前)。①②③は Scene::Draw の中、④⑤は GameEngine::Run が続けて描きます。

    UI モード / 2D モード / 3D モードの違い(SpriteMode)

    SpriteRenderer::SetMode で選びます(既定は UI)。

    SpriteMode::UI(UI モード)SpriteMode::World2D(2D モード)SpriteMode::World3D(3D モード)
    大きさ(z)z で変わらないz で変わらない(遠近なし)z で変わる(奥ほど小さい)
    カメラ2D カメラの位置でスクロール2D カメラの位置でスクロール3D カメラの透視。カメラの方を向く板(ビルボード)
    前後の決まり方必ず最前面。深度を使わない。UI どうしは drawPriority → 作った順(後に作った物が手前)。z は使わないz が小さい(手前)ほど手前(深度バッファ)。UI には隠される深度バッファ。3D メッシュと同じ深度で出たり隠れたりする
    どのパスで描く?パス 2(UI スプライト)パス 1パス 1
    使う場面HUD・ボタン・2D の爆発の粒2D ゲームで z で前後を決めたい物(背景・壁・敵・Player・弾)3D 空間に置く看板・敵の画像
    • 文字(Text::Draw)と四角(Image::DrawRect)は、Scene::Draw の間はその場で描かれず、UI スプライトの後に、呼んだ順で描かれます(Direct2D は命令がたまると途中で画面に出すため、その場で描くと後から描く UI スプライトに隠れてしまうから)。四角を描いてから文字を描けば、四角の上に文字が出ます。
    • 2D と 3D を同じシーンで混ぜることは想定していません(混ぜると深度の値で前後が決まります)。
    • SetWorldSpace(bool) は互換のために残っています(true = World3D、false = UI)。GetDepthScale2D は廃止されました。
    • drawPriority は GameObject::SetDrawPriority で決めます。スカイボックスは INT_MIN、水面は大きい値(100)にします。

    6. 物理とコールバックの流れ

    1 フレームの中で、物理(PhysX)はシーンの Update より先に進みます。ぶつかった時の OnCollisionEnter などは、Physics::Update の中で呼ばれます。

    Physics::Update から、コールバック、そして Scene::Update での位置の同期まで。

    • コールバックは、ぶつかった2 つの GameObject のそれぞれの全 Component に届きます(override した Component だけが反応します)。
    • OnTriggerStay は PhysX が出さない通知なので、Engine が「重なっている組み合わせ」を覚えて、毎フレーム呼んでいます。
    • コールバックの中では PhysX のアクターの追加・削除はできません(予約されて、あとで実行されます)。AddForce は呼んでよく、PhysX の計算の直後にまとめて加わります。
    • Dynamic の物は位置を直接書き換えず、SetVelocity() / AddForce() で動かします。RigidbodyComponent::Update が PhysX の結果を transform に書き戻します。
    • 2D のゲームでは、重力を切り(SetUseGravity(false))、Z を固定(SetFreezePositionZ(true))します。

    8. シーンの切り替えの流れ

    古いシーンの Uninit → 新しいシーンの Init の順。演出付きの時は、画面が覆われている間に切り替わり、その間ゲームの時間は止まります。

    • 古いシーンが使っていた画像・音・モデルは、新しいシーンの Init の後に解放されます(両方のシーンで使う物は読み直さずに使い回せます)。
    • 切り替えのとき、画面エフェクト(Flash / Vignette)とカメラの揺れは消えます。Fade の濃さは残り、onComplete は捨てられます。
    • 演出中は Time の倍率が 0 になります。演出の途中で SetTimeScale を呼んでも、演出が終わってから効きます。
