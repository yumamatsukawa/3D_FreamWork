    Physics(物理と当たり判定)

    Engine/Physics/ は、物理エンジン PhysX 4.1 を使った「動き」と「当たり判定」です。2D のゲームも 3D のゲームも、当たり判定は全部 PhysX が計算しています(2D 専用の物理があるわけではなく、2D 用の使いやすい形(Circle / Square)が用意されています)。 物をぶつけたい時は、GameObject に ○○RigidbodyComponent を付けます。ぶつかった時の反応は、Component の OnCollisionEnter / OnTriggerEnter などを override して書きます。

    Engine/Physics/RigidbodyComponent.h Engine/Physics/RigidbodyComponent.cpp

    物理の剛体(Unity の Rigidbody + Collider を1つにしたもの)です。親クラスの RigidbodyComponent に共通の機能があり、形ごとの子クラスを AddComponent します。Dynamic は PhysX の計算結果が transform に反映され、Kinematic は逆に transform の位置が PhysX に伝わります。

    剛体の種類(BodyType)

    名前引数・戻り値何をするか
    BodyType::Dynamicenum class BodyType重力や衝突で物理的に動く。PhysX の計算結果が Transform に反映される。普通の動く物
    BodyType::Kinematicenum class BodyType自分のコードが Transform を動かす。Dynamic を押せるが、自分は重力や力の影響を受けない
    BodyType::Staticenum class BodyType完全に動かない(床・壁など)

    形ごとのクラス(どれも Component として AddComponent する)

    名前引数・戻り値何をするか
    BoxRigidbodyComponent(BodyType, XMFLOAT3 size, float density, bool isTrigger, bool isStaticForPush)3D の箱。size の既定(0)は Owner の transform.scale
    SphereRigidbodyComponent(BodyType, float radius, float density, bool isTrigger, bool isStaticForPush)3D の球。radius の既定(0)は transform.scale.x の半分
    CircleRigidbodyComponent(同上)2D 用の円。中身は Sphere と同じ(PhysX に2D専用の形は無い)
    SquareRigidbodyComponent(BodyType, float size, float density, bool isTrigger, bool isStaticForPush)2D 用の四角。中身は Box(一辺 size の立方体)
    CapsuleRigidbodyComponent(BodyType, float radius, float height, float density, bool isTrigger, bool isStaticForPush, CapsuleAxis axis)3D のカプセル(円柱の両端が半球)。人や敵向き。axis の既定は Y(立った形)
    Capsule2DRigidbodyComponent(同上)2D 用のカプセル。デバッグ表示は断面だけ
    TerrainRigidbodyComponent(const std::shared_ptr<Terrain>& terrain, bool isTrigger)地形(Terrain)の起伏に合わせた当たり判定。いつも Static

    気を付ける点
    • Dynamic の transform を直接書き換えない。動かす時は SetVelocity() か AddForce() を使います(直接書くと PhysX の計算とぶつかります)。Kinematic だけは transform.position を直接動かしてよい決まりです。
    • SetVelocity / SetUseGravity / SetFreezeRotation / SetFreezePosition○ / AddForce / AddTorque / SetMass / SetDrag は Dynamic にしか効きません(Kinematic / Static では何もせず、出力ウィンドウに1回だけ知らせます)。
    • SetVelocity は 毎回3軸すべてを上書きします。重力で落ちる Y の速さを残したい時は、GetVelocity() で今の値を読んで渡します。
    • 2D のゲームでは SetUseGravity(false) と SetFreezePositionZ(true)(と、回したくなければ SetFreezeRotation(true))を付けるのが決まりです。物理の重力はシーン全体で下向き((0,-981,0))に働くので、2D のトップダウンでは切っておきます(Sample2D の Player が実例)。SquareRigidbodyComponent は奥行きも一辺と同じ長さの立方体です。
    • Kinematic の物と Static の物の間では、衝突のコールバックは来ません(すり抜けます)。PhysX の既定では、Kinematic と Static の組はペアにならないためです(README §38 の記録と一致。Engine には eENABLE_KINEMATIC_STATIC_PAIRS などの設定がありません。実行して確かめたのではなく、PhysX の既定の動きから導いた結論です)。Physics.cpp の CollisionFilterShader のコメントは、ペアができた後の通知の話です。壁にぶつけたい物は Dynamic にして SetVelocity で動かすと、Static の壁と衝突します。
    • isStaticForPush: true だと、Kinematic 同士がぶつかった時に自分は押し戻されない側になります(BodyType::Static とは別の概念)。
    • カプセルを立てたまま回転ロック無しの Dynamic にすると、ぶつかった時に倒れて転がります。人・敵には SetFreezeRotation(true) を付けます。
    • TerrainRigidbodyComponent は、TerrainRenderer に渡したのと 同じ Terrain を渡します(見た目と当たり判定がずれない)。位置は作った時に決まる(後で動かしても当たり判定は動かない)。地形の下側からは通り抜けます。isTrigger は効きません。
    • ForceMode(Force / Impulse / Acceleration / VelocityChange)の違いは次の Physics.h の節の表を見てください。Impulse は重さで割られるので、「速さ × 重さ」を渡すと思った速さで弾かれます。
    • 長さの感覚は 100 単位 = 約 1m です(重力 981 もこのため)。

    Engine/Physics/Physics.h Engine/Physics/Physics.cpp

    PhysX の初期化・毎フレームの更新・終了と、「この線の先に何があるか」「この範囲に何がいるか」を調べる問い合わせ(Raycast / Overlap)です。PhysX の結果を、Component の OnCollisionEnter / OnTriggerEnter などのコールバックに変換して届けるのもここです。

    問い合わせ(ゲーム側から使う)

    名前引数・戻り値何をするか
    Raycast(origin, direction, maxDistance, hit, tag, triggers)boolorigin から direction の向きに最大 maxDistance まで線を飛ばし、最初に当たった物を hit(RaycastHit)に入れる。当たれば true
    OverlapSphere(center, radius, tag, triggers)std::vector<GameObject*>中心 center・半径 radius の球に入っている物を全部探す(2D では円)
    OverlapBox(center, size, tag, triggers)std::vector<GameObject*>中心 center・大きさ size(辺の長さ)の箱に入っている物を全部探す。箱は回転しない

    型

    名前引数・戻り値何をするか
    RaycastHitstructobject(当たった GameObject)、point(当たった場所)、normal(面の向き)、distance(距離)
    ForceModeenum classForce(押し続ける)/ Impulse(一瞬の衝撃。ノックバック)/ Acceleration(質量を無視して押し続ける)/ VelocityChange(質量を無視して一瞬で速さを変える。ジャンプ)
    QueryTriggersenum classIgnore(トリガーを無視。既定)/ Include(トリガーも探す)

    エンジン内部用(ゲーム側からは呼ばない)

    名前引数・戻り値何をするか
    Init()boolPhysX を初期化する(GameEngine が呼ぶ)。重力は (0, -981, 0)
    Update(float dt)void1フレーム分シミュレーションを進め、当たり判定のコールバックを呼ぶ(GameEngine が呼ぶ)。dt が 0(ポーズ中)の時は何もしない
    Uninit()voidPhysX の後片付け(GameEngine が呼ぶ)
    GetPhysics() / GetScene() / GetDefaultMaterial() / GetCooking()PhysX のポインタRigidbodyComponent などが PhysX のアクターを作るために使う
    QueueSceneChange(actor, add)voidPhysX のコールバック中は直接 add / remove できないので、予約して次の Update の安全なタイミングで実行する
    CancelQueuedSceneChange(actor)void予約を取り消す(RigidbodyComponent の Uninit が呼ぶ)
    ForgetTriggerPairs(actor)voidトリガーに重なっている記録を忘れる(RigidbodyComponent が呼ぶ)
    ApplyForce(actor, value, mode, torque)voidAddForce / AddTorque の本体(コールバック中は預かって、あとでまとめて加える)

    気を付ける点
    • tag を指定すると、そのタグのオブジェクトだけを探します("" なら全部)。
    • トリガー(isTrigger=true)は、QueryTriggers::Include を渡した時だけ探します。tag を指定してもトリガーは無視されたままです。
    • 非アクティブ(ObjectPool に戻っている物)や Destroy 済みの物は返しません。
    • 位置は「最後に PhysX が計算した時(このフレームの始め)」のものです。このフレームに出したばかりの物や、動かした直後の Kinematic は、次のフレームから見つかります。
    • Raycast は、origin が中に入っている物には当たりません(自分の中心から飛ばしても、自分には当たらない。Unity と同じ)。direction は長さ 1 でなくてもよい(長さ 0 は false)。
    • 問い合わせは読むだけなので、コールバックの中から呼んでも大丈夫です。
    • PhysX のコールバック(OnCollisionStay など)の中で、アクターの追加・削除はできません。AddForce は呼んでよい(計算の直後にまとめて加わります)。
    • PhysX 4.1 は「トリガーに重なっている間」の通知を出さないため、Engine が組み合わせを覚えて、毎フレーム OnTriggerStay を呼んでいます。

    Engine/Physics/Collider.h Engine/Physics/Collider.cpp

    コールバックで「誰と当たったか」を知らせるための、軽い札です(形や判定の計算は持ちません。判定は PhysX がやります)。型の名前に 2D と付いていますが、3D の剛体でも同じ型が使われます(OnTriggerEnter などのコールバックは 2D・3D 共通)。

    Collider2D::isStaticbool相手が押し戻しで動かない側か(isStaticForPush)
    Collider2D::GetTag()const std::string&相手の GameObject のタグ("Enemy" など)
    CollisionInfo::otherCollider2D*相手のコライダー
    CollisionInfo::normalXMFLOAT2押し戻しの向き
    CollisionInfo::depthfloatめり込んだ量
    IsPointInBox(XMFLOAT2 point, const Transform& transform)bool点が Transform の四角形(回転を考慮)の中にあるか。当たり判定とは独立した、UI のクリック判定などに使う道具
